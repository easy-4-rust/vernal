## 阶段 0：锁定事实

- 固定 Spring 提交与 329 个对象清单。
- 每次变更重跑审计；不得手工改生成台账。

## 阶段 1：先处理 `MISPLACED`

- 将 10 个错位对象移动到末两层目标目录。
- 拆分单文件多公开对象。
- 清理 `lib.rs`/`mod.rs` 类型定义和生产 wildcard import。
- 移动时保持公共重导出兼容，并补路径级测试。

## 阶段 2：补齐 Core 基础链

1. `convert/converter` 与 `convert/support`。
2. `io` 与 `io/support`。
3. `env`、类型描述和 annotation/type metadata。
4. `task/support`、serializer/support、util 子包。

每个对象同时交付中文来源注释和语义测试，禁止先建空文件。

## 阶段 3：逐项裁决平台能力

- ASM/CGLIB/Objenesis/AOT/JFR 对象逐行选择 Rust 实现、精确依赖复用或 `PLATFORM_NA`。
- `PLATFORM_NA` 必须记录 JVM/字节码不可迁移依据和调用方处置。

## 阶段 4：上层回归

Core 对 Beans、Expression、Context、Web 的公开契约做集成回归。只有审计中所有对象进入
`IMPLEMENTED`、`DEPENDENCY_REUSED` 或 `PLATFORM_NA`，模块才可标记完成。
