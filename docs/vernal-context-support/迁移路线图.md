# vernal-context-support 全量迁移路线图

> 版本：v1.0（2026-07-27）｜基线：Spring Framework **7.0.8**（spring-context-support）
> 仓库：easy-4-rust/vernal @ dev ｜ 本文档随代码同步维护，每阶段完成时更新
> 参考：spring-context-support + tx_di

## 一、总目标

以 Spring Framework 7.0.8 的 spring-context-support 模块为蓝本，实现功能语义完全对齐的
vernal-context-support crate，目标 **78+ 个 Rust 文件**（去除 package-info / 内部类），
覆盖 Spring 对**外部生态能力（Caffeine 缓存、JCache、Quartz 调度、JavaMail、FreeMarker）**
的封装，让 Vernal 业务侧可以直接声明式接入这些能力。

### 设计原则

1. **功能语义对齐，实现方式 Rust 化**：
   - Java 反射 → trait 对象 + Arc<dyn Trait>
   - Java SPI / FactoryBean → 过程宏 / 构造函数直接构造
   - JavaMail MimeMessage → Rust 中通过 `lettre` crate（标准邮件库）替代
   - Quartz Scheduler → Rust 中通过 `tokio-cron-scheduler` crate 替代
   - Caffeine 缓存 → Rust 中通过 `moka` crate（功能等价替代）替代
   - JCache (JSR-107) → Rust 中通过 `cacache` 或 `cached` crate 替代
   - FreeMarker → Rust 中通过 `tera` 或 `askama` crate（模板引擎）替代
2. **每个 .rs 文件只对应一个 Java 对象**：对齐 vernal-expression / vernal-context 的一文件一对象规范
3. **所有公开类型必须有中文文档注释**：结构体、枚举、trait、方法、字段
4. **模块路径 snake_case**，类型 PascalCase，方法 snake_case
5. **与 vernal-context 深度集成**：cache/mail/scheduling 子模块依赖 `vernal-context::ApplicationContext`
6. **不实现 Java 生态特有**：JSR-107 规范完整实现、JNDI 绑定、EJB 集成、MIME 严格符合
7. **可插拔 trait 优先**：每个 Spring 类对应一个 Rust trait，便于业务方替换实现

## 四、工程规范

### 命名规则

| 项目 | 规范 |
|------|------|
| 目录/文件名 | snake_case（`transaction_aware_cache_decorator.rs`）|
| 类型名 | PascalCase（`TransactionAwareCacheDecorator`、`CaffeineCache`）|
| 方法名 | snake_case（`get_name`、`put_if_absent`）|
| 参数名 | 与 Java 一致（`target_cache`、`cache_names`）|
| 后端 crate 引用 | trait 抽象，不暴露具体后端类型到公开 API |

### 文件结构规范

```rust
//! 对应 Java 类：org.springframework.cache.transaction.TransactionAwareCacheDecorator
//!
//! 缓存装饰器，将其 put / evict / clear 操作与 Spring 管理的事务同步，
//! 仅在事务成功提交的 after-commit 阶段才执行实际的缓存写操作。
//! 如果没有活动的事务，则立即执行。

use std::sync::Arc;
use crate::cache::{Cache, CacheError};

/// 事务感知缓存装饰器。
///
/// 对应 Spring 的 `TransactionAwareCacheDecorator`，其 `put` / `evict` / `clear`
/// 操作会延迟到事务成功提交后才执行；无事务时立即执行。
///
/// # 注意
///
/// `put_if_absent` 和 `evict_if_present` 这类即时操作**无法**延迟到 after-commit，
/// 在事务环境中请谨慎使用。
pub struct TransactionAwareCacheDecorator {
    /// 被装饰的目标缓存
    target_cache: Arc<dyn Cache>,
}

impl TransactionAwareCacheDecorator {
    /// 创建事务感知缓存装饰器。
    ///
    /// # 参数
    /// - `target_cache`：被装饰的目标缓存
    pub fn new(target_cache: Arc<dyn Cache>) -> Self {
        Self { target_cache }
    }
}

#[async_trait]
impl Cache for TransactionAwareCacheDecorator {
    fn get_name(&self) -> &str {
        self.target_cache.get_name()
    }

    async fn get(&self, key: &dyn std::any::Any) -> Result<Option<Arc<dyn std::any::Any>>, CacheError> {
        self.target_cache.get(key).await
    }

    async fn put(&self, key: &dyn std::any::Any, value: Arc<dyn std::any::Any>) -> Result<(), CacheError> {
        // 注册 afterCommit 回调；无事务时立即执行
        crate::transaction::after_commit(move || {
            let target = self.target_cache.clone();
            let key_arc = ...;
            let value_arc = ...;
            Box::pin(async move {
                target.put(&key_arc, value_arc).await
            })
        }).await
    }
}
```

## 五、风险评估

| 风险 | 影响 | 对策 |
|------|------|------|
| Quartz ↔ tokio-cron-scheduler 语义差异（持久化、集群） | Quartz 的 JDBC 集群模式 Rust 端实现困难 | 仅支持单机模式，文档明确说明 |
| JCache 完整规范实现工作量大 | 19 个 interceptor 类移植成本高 | 大幅精简：保留核心 trait + 1 个实现 |
| JavaMail MimeMessage 完整字段支持 | 90+ 字段全部支持工作量大 | 优先支持常用字段（from/to/subject/text/html/attachments） |
| Caffeine ↔ moka API 差异 | CaffeineSpec 字符串解析需要从零实现 | 实现核心子集（maximumSize / expireAfterWrite / expireAfterAccess） |
| FreeMarker ↔ tera 模板语法差异 | 模板不能直接复用 | 在文档中明确语法差异，提供迁移指南 |
| 大量 Java 生态依赖（JNDI / EJB / JSR-107 完整规范） | 完整迁移不现实 | 仅保留 trait 抽象，业务方自行实现后端 |
