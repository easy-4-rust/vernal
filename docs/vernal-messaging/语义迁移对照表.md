# spring-messaging → vernal-messaging 语义迁移对照表

> 基线：Spring Framework 7.0.8。目标是用户可观察语义完全迁移；Rust 可使用 trait、泛型、过程宏、feature 或 companion crate，但不得将 STOMP、RSocket、TCP、Reactive、完整模板体系永久排除。
> 状态：✅ 已有｜⬜ 待实现｜🔶 Rust 形态不同｜🧩 feature/独立 crate｜🔌 外部桥接。

## 一、消息模型

| Spring 语义 | Rust 语义合同 | 实现 | 状态 | 测试 oracle |
|---|---|---|---:|---|
| Message payload + headers | 泛型 payload 与只读 headers | `Message<T>` | ⬜ | payload/header 身份与类型 |
| MessageHeaders | 标准头、扩展头、不可变快照 | `MessageHeaders` | ⬜ | copy/replace/remove 不改变旧消息 |
| MessageBuilder | 链式构造、条件设置、复制 | `MessageBuilder` | ⬜ | absent/overwrite/copy |
| ErrorMessage | 错误 payload + failed message | `ErrorMessage` | ⬜ | cause 与原消息可追踪 |
| header accessor | 可变构建视图、native headers | `MessageHeaderAccessor` | ⬜ | freeze 后不可变 |

标准头包括 ID、timestamp、contentType、replyChannel、errorChannel；ddd4r 头只能在桥接层命名空间映射，不覆盖标准语义。

## 二、通道、拦截器与确认的边界

| 语义 | Rust 合同 | 状态 | oracle |
|---|---|---:|---|
| MessageChannel.send | 返回发送结果，支持立即/有限/无限 timeout | ⬜ | try、timeout、await 三路径 |
| PollableChannel.receive | 可轮询接收，区分空、超时、关闭 | ⬜ | timeout 与关闭 |
| SubscribableChannel | 独立订阅注册/退订 | ⬜ | 多订阅、顺序、退订后不可投递 |
| ChannelInterceptor | pre/post/after send 和 receive 回调 | ⬜ | 短路、异常、回调顺序 |
| Acknowledgment | delivery 的 Ack/Nack/Requeue 状态机 | 🔌 | settle 后状态、重复确认、重投 |

`Acknowledgment` 不等于 `ChannelInterceptor`：前者决定 broker delivery 的结算，后者观察/修改通道操作。桥接不得用 `after_send_completion` 假装 ack 成功，也不得把 nack 映射成普通发送异常而丢失重投策略。

## 三、处理器调用与映射

| Spring 语义 | Rust 化方式 | 状态 | oracle |
|---|---|---:|---|
| MessageHandler | `handle_message` trait | ⬜ | 错误向发送方/错误通道传播 |
| ReactiveMessageHandler | Publisher/Future 适配与独立 demand 合同 | 🧩 | backpressure/cancel/error/complete |
| InvocableHandlerMethod | 闭包/注册函数 + 参数解析器 | 🔶 | 选择、绑定、返回值与异常 |
| Payload/Header/Message resolver | trait + 过程宏生成绑定 | 🔶 | 缺失 header、类型不符、默认值 |
| MessageMapping | 编译期宏生成路由注册 | 🔶 | pattern、条件、优先级 |
| SendTo/异常处理 | 返回值与异常路由 | ⬜ | reply/error channel 与目的地 |

Rust 不复制 Java 反射，但必须保留“按消息选择处理方法、解析参数、转换返回值、处理异常”的外部结果。

## 四、转换与模板

| Spring 语义 | Rust 实现 | 状态 | oracle |
|---|---|---:|---|
| MessageConverter | `from_message`/`to_message` | ⬜ | 可转换、不可转换、异常分类 |
| SmartMessageConverter | conversion hint | ⬜ | hint 改变目标类型/策略 |
| MIME/content type 协商 | `MimeType` 与 `application/*+json` 匹配 | ⬜ | 精确、通配、无类型 |
| Composite converter | 有序链式委托 | ⬜ | 首个成功、全失败 |
| String/bytes/JSON | 原生实现与 serde feature | ⬜ | 编码、空值、序列化错误 |
| Protobuf/Marshalling | companion feature | 🧩 | 协议格式与错误语义 |
| MessageSendingOperations | send/convertAndSend | ⬜ | post processor 与 header |
| MessageReceivingOperations | receive/receiveAndConvert | ⬜ | timeout 与转换错误 |
| MessageRequestReplyOperations | sendAndReceive | ⬜ | reply correlation、timeout、错误 |
| GenericMessagingTemplate | 组合上述操作 | ⬜ | 完整模板流程 |
| DestinationResolver | 目的地到 channel 的解析 | ⬜ | 未解析目的地明确失败 |

完整模板体系必须迁移；不能因为 Rust 没有 BeanFactory 就删除 `receive` 或 request-reply。BeanFactory 只替换为显式注册表/容器适配。

## 五、路由条件

| Spring 语义 | Rust 实现 | 状态 | oracle |
|---|---|---:|---|
| MessageCondition | `combine`/`get_matching_condition`/`compare_to` | ⬜ | 组合与优先级 |
| DestinationPatterns | Ant/路径变量匹配器 | ⬜ | `order.*`、精确、变量、排序 |
| SimpMessageTypeCondition | STOMP companion | 🧩 | CONNECT/SUBSCRIBE/SEND 等消息类型 |
| RSocketFrameTypeCondition | RSocket companion | 🧩 | frame 类型与 metadata |
| ddd4r TagExpression | 外部 adapter 显式转换 | 🔌 | 通配、或、排除的差异有测试 |

## 六、Reactive 语义

Reactive 不是“把 Reactor 类型换成 tokio Future”就完成。必须提供 Publisher/Subscriber 或等价合同：需求传播、单订阅/多订阅规则、背压、取消、错误和完成信号、线程/执行上下文传播。可以以 `vernal-messaging-reactive` 发布，但其消息、异常、拦截和 handler 合同必须与核心互操作。

## 七、STOMP 语义

`vernal-stomp` 必须覆盖 frame 命令与 headers、CONNECT/CONNECTED、SUBSCRIBE/UNSUBSCRIBE、SEND/MESSAGE、ACK/NACK、receipt、transaction、heartbeat、错误 frame、session 生命周期、simple broker 路由、用户目的地和订阅匹配。WebSocket/TCP 只是 transport，不能替代 STOMP 语义；实现可使用 Rust 协议库，但须通过协议 oracle。

## 八、RSocket 语义

`vernal-rsocket` 必须覆盖 request-response、fire-and-forget、request-stream、request-channel、metadata、payload、错误信号、取消、连接生命周期及服务代理/注解映射。Rust API 形态可以不同，但交互模型和可观察信号必须保持。

## 九、TCP 语义

`vernal-messaging-tcp` 覆盖连接工厂、客户端/服务端连接、帧边界、codec、读写超时、半关闭、异常、重连和背压。`tokio::net` 只提供 transport 原语，不能作为迁移完成的理由。

## 十、ddd4r 外部集成语义

| ddd4r 语义 | `ddd4r-vernal-messaging` 适配 | 不允许的简化 |
|---|---|---|
| MqEvent/EventEnvelope | Message adapter | 不改变 Message 核心定义 |
| MessagePublisher | `PublisherSendAdapter` | 不声明为 SubscribableChannel |
| Delivery/MessageHandler | `DeliveryHandlerAdapter` | 不丢失 delivery metadata |
| Acknowledgment | `SettlementPort` | 不映射为 ChannelInterceptor |
| ConsumerEngine | 外部 runtime adapter | 不放入核心 crate |
| Outbox/Idempotency | ddd4r 自有边界 | 不把存储责任塞进 messaging 核心 |

核心依赖方向只能是：应用 → `vernal-messaging`；外部桥接 → `vernal-messaging` + ddd4r。核心不得依赖 ddd4r。

## 十一、统一测试 oracle

测试不仅检查类型能编译，还要检查用户可观察结果：消息内容与头、通道返回与时序、拦截器触发、handler 参数和异常、转换/模板结果、Reactive 信号、协议 frame/session、broker ack 和重投、桥接后的 receipt 与生命周期。每个 feature/companion crate 需有单元、契约和端到端测试，并在四文档中使用同一术语与状态。
