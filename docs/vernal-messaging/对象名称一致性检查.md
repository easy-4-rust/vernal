# vernal-messaging 对象名称一致性检查

> 检查时间：2026-07-27｜基线：Spring Framework 7.0.8 `spring-messaging`
> 本检查验证四文档的名称、术语、依赖边界和统计口径；它不把“Rust 文件同名”误当作语义完成。

## 一、统一命名规则

| 层级 | 规则 | 示例 |
|---|---|---|
| Java 类型映射 | PascalCase → snake_case | `MessageHeaderAccessor` → `message_header_accessor.rs` |
| Rust 类型 | PascalCase | `MessageChannel`、`GenericMessagingTemplate` |
| Rust 方法 | snake_case | `handle_message`、`send_and_receive` |
| 常量 | UPPER_SNAKE_CASE | `INDEFINITE_TIMEOUT`、`CONTENT_TYPE` |
| 协议 crate | `vernal-*` | `vernal-stomp`、`vernal-rsocket` |
| 外部集成 crate | `ddd4r-vernal-messaging` | 只放桥接，不放核心实现 |

对象名称一致性要求：每个 Spring 对象必须有唯一 Rust 落点记录；合并实现要列出全部对象；feature/companion crate 要写明路径；外部 ddd4r 类型不能冒充 Spring 对偶。

## 四、协议与 Reactive 名称清单

| Spring 包/对象族 | Rust 落点 | 一致性 |
|---|---|---:|
| `messaging.simp` / STOMP | `vernal-stomp` | 🔶 companion crate |
| `messaging.rsocket` | `vernal-rsocket` | 🔶 companion crate |
| `messaging.tcp` | `vernal-messaging-tcp` | 🔶 transport companion |
| `handler.invocation.reactive` | `vernal-messaging-reactive` | 🔶 async-stream 形态 |
| `handler.annotation.reactive` | reactive macros/registry | 🔶 编译期注册 |

检查结论：这些名称不是“排除项”；它们是必须完成的可选模块。若采用 feature 而非独立 crate，feature 名必须保持 `stomp`、`rsocket`、`tcp`、`reactive` 的可识别性，并在对象表登记。

## 五、ddd4r/ddd4j 名称与边界检查

| ddd4r 名称 | 正确位置 | 与 Spring 名称关系 | 禁止写法 |
|---|---|---|---|
| `MqEvent` / `EventEnvelope` | `ddd4r-vernal-messaging` | Message 的外部适配输入 | 核心实现 `MqEvent: Message` 并反向依赖 ddd4r |
| `MessagePublisher` | `PublisherSendAdapter` | 发送能力适配 | 直接称为 `SubscribableChannel` |
| `Acknowledgment` | `SettlementPort`/adapter | delivery settlement | 写成 `ChannelInterceptor` |
| `ConsumerEngine` | `consumer_engine_runtime` | 消费运行时 | 放入 `vernal-messaging` |
| `TagExpression` | `tag_condition_adapter` | 路由表达式适配 | 宣称与 Ant pattern 完全同构 |
| ddd4j headers | 外部映射命名空间 | 可映射 metadata | 覆盖 Spring 标准 header |

## 六、统计与术语门禁

1. 四文档只使用“核心 crate”“feature/companion crate”“外部桥接 crate”三种迁移位置。
2. 不再使用“STOMP/RSocket/TCP/Reactive 共 X 个不迁移”作为结论；正确表述是“在 S8-S11 由 feature 或 companion crate 实现”。
3. “Ack/确认”“拦截器”“发布”“订阅”“消费运行时”必须分别使用，不能互换。
4. 路线阶段固定为 S0-S13；任何新增阶段必须同步更新四文档。
5. 对象计数以对象清单为准，Rust 文件数只作工程规模指标，不能作为覆盖率。
6. 每个对象或对象族必须关联用户可观察 oracle；没有 oracle 的条目只能是规划状态。

## 七、检查结果

| 项目 | 结果 |
|---|---|
| 四文件名称 | 与用户批准范围完全一致 |
| 中文与表格 | 已统一 |
| S0-S13 | 已统一 |
| 完整模板体系 | 已纳入 |
| STOMP/RSocket/TCP/Reactive | 已纳入 feature/companion 路线 |
| ddd4r 核心依赖边界 | 已改为外部 `ddd4r-vernal-messaging` |
| Ack / interceptor | 已明确分离 |
| Publisher / SubscribableChannel | 已明确分离 |
| ConsumerEngine | 已明确不属于核心 |
| 测试 oracle | 四文档均有对应约束 |

最终命名结论：Spring 对象名称在 Rust 中保持可识别的一一落点；Rust 化只改变实现形态，不改变用户可观察语义。ddd4r 类型通过外部桥接命名，不污染 `vernal-messaging` 核心命名空间。
