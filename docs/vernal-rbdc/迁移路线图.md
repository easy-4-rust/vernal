## 一、总目标

以 **Spring JDBC 7.0.8 的功能语义**为蓝本，**以 rbdc 的 Rust 实现结构**为工程化模板，构建 **vernal-rbdc** 这个 **纯 Rust、零反射、trait 驱动、async-first** 的数据库访问层，实现 **功能语义完全迁移**：每个 Spring JDBC 类 → 一个对应的 Rust 文件或显式记录"已合并/不迁移"。

### 设计原则

1. **功能语义对齐，实现方式 Rust 化**：Java `DataSource`/`Connection`/`RowMapper`/`JdbcTemplate` → trait 对象 + `async-trait`/`BoxFuture`；反射 → trait 对象；`BeanFactory` 集成 → `vernal-core::Container`；`Statement`/`ResultSet` → `rbs::Value` + 适配 trait
2. **每个 `.rs` 文件只对应一个 Spring JDBC 对象**（`package-info`、`JdbcDaoSupport` 等聚合类除外）；对齐 `rbdc/src/` 一文件一对象规范
3. **Spring JDBC 不实现的，rbdc 已实现的，vernal-rbdc 直接继承语义**：例如 `rbdc::db::Placeholder`、`StatementCache`、`impl_exchange` 占位符替换
4. **所有公开类型必须有中文文档注释**：结构体、枚举、trait、方法、字段
5. **模块路径 snake_case**，类型 PascalCase，方法 snake_case
6. **与 vernal 框架深度集成**：`DataSource` 可作为 `vernal-core::Component` 注入；事务管理器桥接 `vernal-tx`
7. **驱动以生态 crate 形式发布**：`vernal-rbdc-mysql`、`vernal-rbdc-pg`、`vernal-rbdc-sqlite` 等，与 spring-jdbc + spring-jdbc + 各数据库驱动对应
8. **不实现 Java 生态特有行为**：`NativeJdbcExtractor`、`UserCredentialsDataSourceAdapter`（Java JNDI 用户凭据）、`ShardingKeyDataSourceAdapter`（Java `javax.sql.XADataSource` 分片键）由 Rust 化对应物替代

### vernal-rbdc 在生态中的层级定位

vernal-rbdc **不定义 ORM 标准**，它是 **Java JDBC / spring-jdbc 在 Rust 生态的语义等价层**——位于"驱动"之上、"ORM"之下。

| 层级 | Java 标准 | Rust 生态（现状）| vernal 框架定位 |
|------|-----------|-------------------|----------------|
| **ORM 抽象层** | `javax.persistence.*` / Hibernate | toasty（tokio 官方 ORM）/ rbatis / sea-orm / diesel | 生态承担（不重复造轮子）|
| **JDBC 抽象层** | `spring-jdbc`（基于 `java.sql`）| **无统一抽象**，sqlx 偏裸、diesel 自实现 | **vernal-rbdc**（本文路线图）|
| **事务抽象层** | `spring-tx`（基于 `jakarta.transaction`）| 无统一抽象 | vernal-tx（已存在）|
| **连接池** | HikariCP / DBCP | sqlx pool / bb8 / deadpool | vernal-rbdc-pool-fast（继承自 rbdc-pool-fast）|
| **驱动** | `java.sql.Driver` | mysql_async / sqlx-mysql / tokio-postgres / rbdc-* | vernal-rbdc-mysql / vernal-rbdc-pg / ... |

**关键定位声明**：

- vernal-rbdc **对标 spring-jdbc，不对标 spring-data-jpa**——前者是 JDBC 抽象，后者是 ORM 抽象
- vernal-rbdc **不与 toasty / rbatis 竞争**——它是它们可以依赖的下层；rbatis 本来就基于 rbdc 实现
- vernal-rbdc 的 `DataSource` / `Connection` / `RowMapper` / `JdbcTemplate` 都是 **trait** + **struct** 组合，可作为 toasty / rbatis / sea-orm 的底层选项
- 与 `vernal-tx` 集成提供事务一致性，与 `vernal-core` 集成提供 IoC 注入

> 类比总结：**`spring-jdbc + spring-tx` 在 Rust 生态的等价组合是 `vernal-rbdc + vernal-tx`**；Hibernate 的 Rust 等价不是 vernal-rbdc，而是 toasty / rbatis / sea-orm。

## 五、工程规范

### 命名规则

| 项目 | 规范 |
|------|------|
| 目录/文件名 | snake_case（`jdbc_template.rs`、`data_source.rs`）|
| 类型名 | PascalCase（`JdbcTemplate`、`DataSource`）|
| 方法名 | snake_case（`query`、`query_for_object`、`update`）|
| 参数名 | 与 Java 一致（`sql`、`params`、`row_mapper`）|

### 文件结构规范

```rust
//! 对应 Java 类：org.springframework.jdbc.core.JdbcTemplate
//!
//! JdbcTemplate 是 Spring JDBC 的核心类，封装 JDBC 操作的样板代码。
//! 提供 query/queryForObject/queryForList/update/batchUpdate/execute 等方法。

/// JdbcTemplate 是 Spring JDBC 的核心入口。
///
/// 对应 Spring 的 `JdbcTemplate`，支持：
/// - 查询：`query`, `query_for_object`, `query_for_list`, `query_for_map`, `query_for_row_set`
/// - 更新：`update`, `batch_update`, `execute`
/// - 回调：`ConnectionCallback`, `StatementCallback`, `PreparedStatementCallback`
pub struct JdbcTemplate {
    /// 数据源（来自 spring-jdbc DataSource）
    data_source: Arc<dyn DataSource>,
}

impl JdbcTemplate {
    /// 创建 JdbcTemplate 实例。
    pub fn new(data_source: Arc<dyn DataSource>) -> Self {
        Self { data_source }
    }
}
```

## 六、风险评估

| 风险 | 影响 | 对策 |
|------|------|------|
| 数据源 / JdbcTemplate 接口表面巨大 | 工期长 | 分阶段实施，先常用接口再覆盖冷门 |
| 嵌入式数据库（D/H2/Hsql/Derby）在 Rust 生态不可用 | 跳过功能 | 只保留 trait + 注释驱动跳过 |
| JNDI 在 Rust 生态无对应物 | Lookup 部分接口无意义 | 用 trait + trait_object 替代，文档说明 |
| ShardingKeyDataSourceAdapter 基于 `javax.sql.XADataSource` | 不适用 | 标注 🚫，由分布式事务 crate 替代 |
| LOB 流程依赖 JDBC 与驱动特殊协议 | 端到端测试困难 | 先实现 trait 与类型，运行期依赖驱动实现 |
| SqlRowSet 脱壳 ResultSet 需要完整循环 | 复杂 | 直接借力 rbdc 的 `exec_decode` 返回的 `Value::Array` |
