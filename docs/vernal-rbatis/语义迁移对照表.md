# rbatis + rbatis-cache + spring-orm → vernal-rbatis 功能语义迁移对照表

> 基线：
> - rbatis **4.9.6**（Executor / Intercept / TransactionListener / 内置 cache）
> - rbatis-cache **0.1.0-alpha.2**（CacheBackend SPI / LocalBackend / Redis / Memcached）
> - spring-orm **7.0.8**（ORM 集成层 / 事务管理器 / 异常翻译 / 资源持有 / 线程同步）
>
> 迁移原则：**功能语义对齐，实现方式 Rust 化**。
> Java 的反射 → trait 对象；字节码/JIT → 不需要；MethodHandle → 闭包；
> ClassLoader → 模块路径；TransactionSynchronizationManager → `vernal_t::TransactionSynchronizationManager`。

### 3.1 事务资源绑定（关键时序）

```rust
// RbTransactionManager::do_begin 伪代码
let conn = pool.get().await?;
let mut conn_holder = ConnectionHolder::new(conn);
if definition.is_read_only() { conn_holder.set_read_only(true); }

let mut tx_obj = RbTransactionObject::new(conn_holder);
if let Some(ds) = &self.data_source {
    // 通过 dialect 从 Executor 取出底层 Connection，绑定到线程
    let raw_con = executor.dialect.get_jdbc_connection(&conn)?;
    let con_holder = ConnectionHolder::new(raw_con);
    VernalTransactionSynchronizationManager::bind_resource(ds.as_ref(), con_holder);
}
VernalTransactionSynchronizationManager::bind_resource(self.rb.as_ref(), tx_obj.entity_manager_holder());

let sync = RbTransactionSynchronization::new(
    tx_obj.entity_manager_holder(),
    self.rb.as_ref(),
    ORDER_ENTITY_MANAGER_SYNCHRONIZATION,  // 比 ConnectionHolder 早 -100
);
VernalTransactionSynchronizationManager::register_synchronization(sync);

conn.begin()?;  // 真正的 conn.begin
Ok(())
```

### 6.1 缓存 get_or_load 流水（CacheInterceptor）

```rust
pub async fn get_or_load<F, Fut>(
    &self,
    request: CacheRequest<'_>,
    loader: F,
) -> Result<Vec<u8>, CacheError>
where
    F: FnOnce() -> Fut,
    Fut: Future<Output = Result<Vec<u8>, CacheError>>,
{
    // 1. 解析 SQL（旁路判定：非 Select 一律旁路）
    let sql_meta = match SqlMetadata::parse(request.sql) {
        Ok(m) if m.kind == StatementKind::Select => m,
        _ => return loader().await,
    };

    // 2. 事务中旁路（缓存延迟到 commit）
    if request.in_transaction { return loader().await; }

    // 3. 读 generation（fail-open）
    let generation = match self.backend.generation(request.namespace).await {
        Ok(g) => g,
        Err(_) => { self.metrics.record_backend_error(); return loader().await; }
    };

    // 4. 构造 CacheKey（BLAKE3 摘要）
    let key = CacheKey::build(&input, generation, &sql_meta.table_tags)?;

    // 5. singleflight 锁 + double-check
    let flight = self.singleflight.entry(key.digest.clone()).or_insert_with(...).clone();
    let _guard = flight.lock().await;
    if let Some(bytes) = self.backend.get(&key.digest).await? {
        self.metrics.record_hit();
        return Ok(bytes);
    }

    // 6. 真正加载
    let payload = loader().await?;
    self.metrics.record_load();

    // 7. 写 backend（fail-open）
    let envelope = CacheEnvelope::new(&key, payload.clone(), self.policy.ttl);
    if let Err(_) = self.backend.put(&key.digest, envelope.encode()?, self.policy.ttl).await {
        self.metrics.record_backend_error();
        // 仍返回 payload，不阻塞
    }
    Ok(payload)
}
```

### 6.2 缓存击穿 / 穿透 / 雪崩应对

| 风险 | 应对策略 | vernal-rbatis 实现位置 |
|---|---|---|
| **缓存击穿** | per-key DashMap singleflight + double-check | `cache::singleflight::SingleFlight` |
| **缓存穿透** | 仅缓存 sqlparser 解析后的 Select；非 Select 旁路 | `cache::cache_interceptor::get_or_load` line 旁路判定 |
| **缓存雪崩** | namespace generation 自增失效；TTL 由 envelope + backend 双重防护 | `cache::envelope::CacheEnvelope::is_fresh` |
| **backend 故障** | 全部 fail-open 到 loader + metrics 可观测 | `cache::cache_interceptor` 三处 fail-open |

### 8.2 vernal-rbatis 的 @Transactional 拦截器

```rust
// vernal-aop 风格：方法拦截 + 自动事务
pub struct RbTransactionAdvice {
    tx_manager: Arc<RbTransactionManager>,
}

impl Advice for RbTransactionAdvice {
    async fn around<F, Fut>(&self, join_point: F) -> Result<T, AopError>
    where
        F: FnOnce() -> Fut,
        Fut: Future<Output = Result<T, AopError>>,
    {
        let status = self.tx_manager.get_transaction(&DefaultDefinition)?;
        match join_point().await {
            Ok(ret) => { self.tx_manager.commit(status)?; Ok(ret) }
            Err(e) => { self.tx_manager.rollback(status)?; Err(e) }
        }
    }
}
```
