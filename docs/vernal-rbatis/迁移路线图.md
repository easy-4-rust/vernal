# vernal-rbatis 全量迁移路线图

> 版本：v1.0（2026-07-27）｜基线：rbatis **4.9.6** + rbatis-cache **0.1.0-alpha.2** + Spring Framework **7.0.8**（spring-orm）
> 仓库：easy-4-rust/vernal @ dev ｜ 本文档随代码同步维护，每阶段完成时更新

## 一、总目标

以 **spring-orm（Spring 7.0.8，ORM 集成层抽象与事务管理）** 为"集成层蓝本"，
以 **rbatis 4.9.6** 为"SQL Toolkit / 执行器抽象"蓝本，
以 **rbatis-cache 0.1.0-alpha.2** 为"二级缓存 SPI"蓝本，
实现功能语义完全对齐的 vernal-rbatis crate，目标 **80+ 个 Rust 文件**，
覆盖 RBatis 核心（Executor / Intercept / TransactionListener）、
动态 SQL（PySQL / HTML SQL / CRUD 宏执行期支撑）、
缓存抽象（CacheBackend / CachePolicy / CacheInterceptor）以及
面向 Spring 风格 ORM 集成的资源绑定、线程事务同步、异常翻译层。

### 设计原则

1. **三层对位**：
   - **资源/连接层**：对位 spring-jdbc 的 `DataSourceUtils` 与 spring-orm 的 `EntityManagerHolder`
     → vernal-rbatis 的 `ConnectionHolder` / `RBatisConnExecutor`
   - **执行/拦截层**：对位 rbatis 的 `Executor` trait + `Intercept` trait
     → vernal-rbatis 的 `Executor` + `Intercept` 同名 trait
   - **集成/同步层**：对位 spring-orm 的 `JpaTransactionManager` + `SpringSessionSynchronization`
     → vernal-rbatis 的 `RbTransactionManager` + `RbTransactionSynchronization`
2. **Java 反射 → trait 对象**；**字节码/JIT → 不需要**；**MethodHandle → 闭包**；
   **ClassLoader → 模块路径**；**TransactionSynchronizationManager → `VernalTransactionSynchronizationManager`**
3. **每个 .rs 文件只对应一个核心对象**（对齐 vernal-expression 一文件一对象规范）
4. **所有公开类型必须有中文文档注释**：结构体、枚举、trait、方法、字段
5. **模块路径 snake_case**，类型 PascalCase，方法 snake_case
6. **不实现字节码编译**：Rust 编译器已优化，无需运行时 JIT
7. **缓存 SPI 契约测试强制**：`CacheBackend` 必须通过 4 条契约断言（参考 rbatis-cache/src/testing.rs）
8. **失败开放（fail-open）原则**：缓存后端故障时必须能旁路到 loader，不阻塞数据库访问

| `tx/resource_holder_support.rs` | `ResourceHolderSupport`（spring-tx） | 0.25 天 |
| `tx/transaction_synchronization_manager.rs` | `TransactionSynchronizationManager`（spring-tx，**本地简化版**） | 0.5 天 |

**关键设计（事务绑定）**：
```rust
pub struct RbTransactionManager {
    rb: Arc<RBatis>,
    data_source: Option<Arc<dyn DataSource>>,
}

impl PlatformTransactionManager for RbTransactionManager {
    fn do_get_transaction(&self) -> Box<dyn TransactionObject>;
    fn do_begin(&self, tx: &mut dyn TransactionObject, def: &TransactionDefinition);
    fn do_commit(&self, status: DefaultTransactionStatus);
    fn do_rollback(&self, status: DefaultTransactionStatus);
    fn do_cleanup_after_completion(&self, tx: &mut dyn TransactionObject);
}
```

`RbTransactionObject` 持有 `ConnectionHolder`（含 Arc<Mutex<Box<dyn Connection>>>），通过 `VernalTransactionSynchronizationManager.bind_resource(data_source, holder)` 绑定到线程。

**验收**：

## 五、与 rbatis 原项目的差异策略

| 维度 | rbatis | vernal-rbatis | 策略 |
|------|--------|---------------|------|
| 编译期宏 | `#[sql]` / `#[py_sql]` / `#[html_sql]` / `crud!` | **不在 vernal-rbatis**，由上层 crate 提供 | vernal-macros crate 后续提供 |
| 运行时反射 | 几乎无 | 几乎无 | 保持 |
| 异步模型 | `async-trait` + `BoxFuture` | 同 | 保持 |
| 数据库驱动 | rbdc | vernal-rbdc（独立 crate，对位 rbdc） | 新建 vernal-rbdc crate |
| 二级缓存 | 内置 moka | rbatis-cache + vernal-cache | 双 backend：local（DashMap） + redis |
| Spring 集成 | 无 | vernal-tx + vernal-aop 深度集成 | **vernal-rbatis 独有扩展** |

## 六、关键风险与缓解

| 风险 | 缓解 |
|------|------|
| 事务绑定在多线程下泄漏 | `Arc::strong_count == 2` 启发式清理；显式 `try_with_resource` 模式 |
| 缓存与数据库不一致 | namespace generation 自增；事务 commit 后才刷缓存；DML 后缓存失效 |
| 大量并发连接的 pool 调度 | 复用 vernal-rbdc（对位 rbdc-pool-fast） |
| 过程宏生态缺失 | S4 只提供 AST 公开类型，不重做宏；由 vernal-macros crate 单独演进 |
| 与 spring-orm 的差异（无 FactoryBean 风格入口） | S10 提供 `RbFactoryBean`，支持按 type 注入 Executor 子类型 |
