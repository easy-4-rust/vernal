## 四、统一技术约束

### 4.1 Rust 工程约束

| 约束项 | 要求 | 说明 |
|:---|:---|:---|
| Rust Edition | **2024** | Cargo.toml `edition = "2024"` |
| MSRV | **1.88** | `rust-version = "1.88"` |
| unsafe | **forbid** | Workspace lint: `unsafe_code = "forbid"` |
| 运行时 | **Tokio-first** | 直接使用 Tokio 任务、同步、取消和时间原语 |
| 错误处理 | **thiserror 2.0** | 结构化错误，正常控制流不 panic |
| Resolver | **3** | Cargo resolver version 3 |

### 4.2 架构约束

| 约束项 | 要求 |
|:---|:---|
| 一文件一对象 | 每个 `.rs` 文件只定义一个主要公开类型 |
| mod.rs 只声明 | `mod.rs` 仅包含 `mod` 和 `pub use` 声明 |
| 不泄漏第三方类型 | 公共 API 不暴露 Tokio、serde 等第三方具体类型 |
| 集成模式 A | Adapter 依赖公共合同，内核不反向依赖 Adapter |
| 集成模式 B | 消费方 Bridge 由消费方仓库拥有（如 hutool-vernal） |
| 集成模式 C | IoC 不认识具体 Web 框架类型，框架类型留在 Adapter |
| 集成模式 D | 配置格式加载留在 Adapter，PropertySource 是格式中立端口 |

### 4.3 选型约束

- 以各模块独立文档中的**选型约定章节**为准
- Web 运行时适配统一使用 **Topcoat** 方案（vernal-web + 10 个 adapter crate）
- ORM 集成使用 **Toasty** 方案（vernal-orm 桥接 RBatis）
- 消息中间件统一归入 **vernal-messaging**（spring-jms 不单独建 crate）
- spring-instrument、spring-jcl、spring-oxm **不迁移**（Rust 生态有原生替代）

### 4.4 文档约束

每个模块必须维护 4 份独立文档：

| 文档类型 | 文件名模式 | 内容 |
|:---|:---|:---|
| 迁移路线图 | `{spring}到{vernal}迁移路线图.md` | 阶段划分、里程碑、退出条件 |
| 对象级对照表 | `{spring}到{vernal}对象级对照表.md` | Java 类 → Rust 结构体/trait/枚举逐项映射 |
| 语义迁移对照表 | `{spring}到{vernal}语义迁移对照表.md` | Java 语义（反射/字节码/泛型擦除）→ Rust 等价物 |
| 对象名称一致性检查 | `{spring}到{vernal}对象名称一致性检查.md` | 命名规范审查、snake_case/PascalCase 一致性 |
