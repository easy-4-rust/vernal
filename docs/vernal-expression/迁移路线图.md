# vernal-expression 全量迁移路线图

> 版本：v1.1（2026-07-30）｜基线：Spring Framework **7.0.8**（spring-expression）
> 仓库：easy-4-rust/vernal @ dev ｜ 本文档随代码同步维护，每阶段完成时更新
> **测试**：1,390 passing / 覆盖率 80.51% lines / 71.39% functions

## 一、总目标

以 Spring Framework 7.0.8 的 spring-expression 模块为蓝本，实现功能语义完全对齐的
vernal-expression crate，目标 **87+ 个 Rust 文件**，覆盖 SpEL 全部 AST 节点、
解析器、求值上下文和支撑组件。

### 设计原则

1. **功能语义对齐，实现方式 Rust 化**：Java 反射 → trait 对象；字节码编译 → 不需要；
   MethodHandle → 闭包；ClassLoader → 模块路径
2. **每个 .rs 文件只对应一个 Java 对象**：对齐 liteflow-rust 的一文件一对象规范
3. **所有公开类型必须有中文文档注释**：结构体、枚举、trait、方法、字段
4. **模块路径 snake_case**，类型 PascalCase，方法 snake_case
5. **与 vernal 框架深度集成**：`EvaluationContext` 可桥接 `vernal-context::ApplicationEnvironment`
6. **不实现字节码编译**：Rust 编译器已优化，无需运行时 JIT

## 四、工程规范

### 命名规则

| 项目 | 规范 |
|------|------|
| 目录/文件名 | snake_case（`op_plus.rs`、`compound_expression.rs`）|
| 类型名 | PascalCase（`OpPlus`、`CompoundExpression`）|
| 方法名 | snake_case（`get_value`、`is_compilable`）|
| 参数名 | 与 Java 一致（`expression_string`、`root_object`）|

### 文件结构规范

```rust
//! 对应 Java 类：org.springframework.expression.spel.ast.OpPlus
//!
//! 加法运算符（+）和字符串连接。
//! 支持数值类型和字符串类型的加法操作。

/// 加法运算符节点。
///
/// 对应 Spring 的 `OpPlus`，支持：
/// - 数值加法：`1 + 2` → `3`
/// - 字符串连接：`'hello' + ' world'` → `'hello world'`
/// - 一元正号：`+42` → `42`
pub struct OpPlus {
    /// 左操作数
    left: Box<dyn SpelNode>,
    /// 右操作数
    right: Box<dyn SpelNode>,
}

impl OpPlus {
    /// 创建加法运算符节点。
    pub fn new(left: Box<dyn SpelNode>, right: Box<dyn SpelNode>) -> Self {
        Self { left, right }
    }
}
```

## 五、风险评估

| 风险 | 影响 | 对策 |
|------|------|------|
| SpEL 语法复杂度高 | 解析器实现困难 | 分阶段实现，先支持常用子集 |
| 反射替代方案不完整 | 属性/方法访问受限 | 用 trait 对象 + 闭包替代 |
| 与 vernal 框架集成复杂 | 集成测试困难 | 先独立实现，再集成 |
| 中文注释工作量大 | 交付延迟 | 分阶段进行，优先覆盖核心文件 |
