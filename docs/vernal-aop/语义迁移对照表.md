# aspect-rs → vernal-aop 功能语义迁移对照表

主线：**aspect-rs** @ main（aspect-core 0.1.2 + aspect-macros + aspect-std）
语义参考：Spring Framework **7.0.8** spring-aop（208 类）

迁移原则：**aspect-rs 为实现主线**（Rust 原生，无范式转换），
**spring-aop 为语义参考**（功能完整度标尺）。
核心改造是**异步化**（aspect-rs 同步 → vernal-aop Tokio-first 异步）和
**与现有 Operation/InvocationPlan 体系融合**。

**术语映射说明**：Java 的 `@Annotation` 在 Rust 中用 **derive macro** 或 **attribute macro** 替代。
行为型注解（如 `@Aspect`、`@Transactional`）→ attribute macro；数据型注解（如 `@Data`）→ derive macro。
Spring 的注解分散在各个模块中，Rust 迁移时宏也应在各自模块的 `advice/` 目录下。

状态图例：✅ 已迁移并有测试 / 🔀 语义已迁移待改造 / 🔶 语义等价但形态不同（仅参考）/
⬜ 待移植（S1/S2/S3 路线图）/ 🚫 不移植（已有等价物）/ 🆕 vernal-aop 侧扩展

## 一、Aspect 通知体系（核心，4 类 Advice）

aspect-rs 的 `Aspect` trait 定义 **before/after/after_error/around** 四段式同步通知。
vernal-aop 移植时改造为 **Tokio-first 异步**，并保留 around 的默认实现模式。

| aspect-rs 方法 | 语义 | spring-aop 语义参照 | vernal-aop 实现（异步）| 状态 |
|---|---|---|---|---|
| `Aspect::before(&self, ctx: &JoinPoint)` | 方法执行前调用 | `MethodBeforeAdvice.before()` | `Aspect::before(&self, inv: &Invocation) -> Pin<Box<dyn Future<Output = Result<(), InvocationError>> + Send>>` | ✅ S1 已完成 |
| `Aspect::after(&self, ctx: &JoinPoint, result: &dyn Any)` | 方法成功后调用 | `AfterReturningAdvice.afterReturning()` | `Aspect::after(&self, inv: &Invocation, result: &InvocationValue) -> Pin<Box<dyn Future<Output = ()> + Send>>` | ✅ S1 已完成 |
| `Aspect::after_error(&self, ctx: &JoinPoint, error: &AspectError)` | 方法异常时调用 | `ThrowsAdvice`（反射）| `Aspect::after_error(&self, inv: &Invocation, error: &InvocationError) -> Pin<Box<dyn Future<Output = ()> + Send>>` | ✅ S1 已完成 |
| `Aspect::around(&self, pjp: ProceedingJoinPoint) -> Result<Box<dyn Any>, AspectError>` | 包裹整个执行 | `MethodInterceptor.invoke()` | `Aspect::around(&self, inv: Arc<Invocation>, next: Next) -> InvocationFuture` | ✅ S1 已完成 |

### Advice 语义对比（aspect-rs 同步 vs vernal-aop 异步）

| 语义点 | aspect-rs（同步）| vernal-aop（异步目标）|
|---|---|---|
| 返回值类型 | `Result<Box<dyn Any>, AspectError>`（Box 动态分发）| `InvocationResult`（async，强类型）|
| 执行控制 | `ProceedingJoinPoint::proceed()`（同步）| `Next::run().await`（异步）|
| 上下文 | `JoinPoint`（function_name/module_path/location）| `Invocation`（operation/context/cancellation/deadline）|
| 线程安全 | `Aspect: Send + Sync` | `Aspect: Send + Sync + 'static` |
| around 默认实现 | before → proceed → after/after_error | **保留同模式**（异步化）|

### Aspect trait 默认实现的移植

**aspect-rs 原版**（同步默认实现）：
```rust
fn around(&self, pjp: ProceedingJoinPoint) -> Result<Box<dyn Any>, AspectError> {
    let ctx = pjp.context().clone();
    self.before(&ctx);              // 先 before
    let result = pjp.proceed();     // 执行
    match &result {
        Ok(value) => self.after(&ctx, value.as_ref()),        // 成功 after
        Err(error) => self.after_error(&ctx, error),          // 失败 after_error
    }
    result
}
```

**vernal-aop 移植版**（异步默认实现，保留同模式）：
```rust
async fn around(&self, inv: Arc<Invocation>, next: Next) -> InvocationResult {
    self.before(&inv).await?;                          // before 失败则短路
    let result = next.run().await;                     // 执行
    match &result {
        Ok(value) => self.after(&inv, value).await,    // 成功 after
        Err(error) => self.after_error(&inv, error).await, // 失败 after_error
    }
    result
}
```

### Aspect 与现有 Interceptor 的关系（关键设计决策）

| 项 | 现有 `Interceptor` | 新增 `Aspect` |
|---|---|---|
| 定位 | 底层执行原语（Around-only）| 用户友好门面（四段式）|
| Advice 类型 | 1（around）| 4（before/after/after_error/around）|
| 异步 | ✅ Tokio-first | ✅ Tokio-first |
| 谁实现 | 框架内部 / 高级用户 | 普通用户 |
| 转换 | — | `AspectAdapter` 自动转为 `Interceptor` |

**决策**：现有 `Interceptor` 保留为底层，新增 `Aspect` 作为门面，两者通过
`AspectAdapter` 桥接。这样既保留 vernal-aop 现有优势，又获得 aspect-rs 的用户友好性。

### spring-aop 6 类 Advice 的覆盖情况

| spring-aop Advice | aspect-rs 覆盖 | vernal-aop 实现 | 状态 |
|---|---|---|---|
| `MethodBeforeAdvice` | ✅ `Aspect::before` | `Aspect::before`（异步）| ⬜ S1 |
| `AfterReturningAdvice` | ✅ `Aspect::after` | `Aspect::after`（异步）| ⬜ S1 |
| `ThrowsAdvice` | ✅ `Aspect::after_error` | `Aspect::after_error`（异步）| ⬜ S1 |
| `MethodInterceptor`（around）| ✅ `Aspect::around` | `Aspect::around` + 现有 `Interceptor`（异步）| ⬜ S1 |
| `AfterAdvice`（finally）| 🔶 `after` + `after_error` 组合 | 合并到 `Aspect::after`（finally 语义）| 🔶 |
| `IntroductionAdvice` | ❌ 未覆盖 | S5 补 `IntroductionAdvisor` | ⬜ S5 |

**覆盖率**：aspect-rs 覆盖 spring-aop **5/6 核心 Advice**（83%），仅 Introduction 需 S5 补齐。

## 二、JoinPoint 体系（3 类 → 🔶 复用现有，不移植）

| aspect-rs 类型 | 语义 | spring-aop 语义参照 | vernal-aop 现有等价 | 状态 |
|---|---|---|---|---|
| `JoinPoint`（function_name/module_path/location）| 静态连接点 | `JoinPoint`/`MethodInvocation` | `Operation`（component/method/metadata）| 🔶 复用 |
| `Location`（file:line）| 源码位置 | （静态位置）| （可加入 OperationMetadata）| 🔶 复用 |
| `ProceedingJoinPoint`（proceed 控制）| around 的执行控制 | `ProceedingJoinPoint.proceed()` | `Next`（run().await）| 🔶 复用 |

### JoinPoint vs Operation 语义对比

| 字段/方法 | aspect-rs `JoinPoint` | vernal-aop `Operation` | 优势 |
|---|---|---|---|
| 函数名 | `function_name: &'static str` | `method: Arc<str>` | vernal 更灵活 |
| 模块路径 | `module_path: &'static str` | `component: Arc<str>` | 等价 |
| 源码位置 | `location: Location`（file/line）| （无，可扩展）| aspect-rs 有 |
| 元数据 | （无）| `metadata: OperationMetadata`（tags/qualifier）| **vernal 更强** |
| 全限定名 | `qualified_name() -> String` | `Display`（`component::method`）| 等价 |

**结论**：`Operation` 是 `JoinPoint` 的超集（多了 tags/qualifier），无需移植 `JoinPoint`。

### ProceedingJoinPoint vs Next

| 行为 | aspect-rs `ProceedingJoinPoint` | vernal-aop `Next` |
|---|---|---|
| 执行原始函数 | `pjp.proceed() -> Result<Box<dyn Any>, AspectError>`（同步）| `next.run().await -> InvocationResult`（异步）|
| 获取上下文 | `pjp.context() -> &JoinPoint` | `inv.operation() -> &Operation`（通过 Invocation 参数）|
| 消费性 | `proceed(self)` | `run(self)` |

**结论**：`Next` 是 `ProceedingJoinPoint` 的异步等价物，无需移植。

#### Matcher 实现语义（移植 + 改造）

**aspect-rs 原版**（为 Pointcut/ExecutionPattern/ModulePattern 实现 Matcher）：
```rust
impl Matcher for Pointcut {
    fn matches(&self, function: &FunctionInfo) -> bool {
        match self {
            Pointcut::Execution(p) => p.matches(function),
            Pointcut::Within(p) => p.matches(function),
            Pointcut::And(l, r) => l.matches(function) && r.matches(function),
            Pointcut::Or(l, r) => l.matches(function) || r.matches(function),
            Pointcut::Not(inner) => !inner.matches(function),
        }
    }
}
```

**vernal-aop 移植版**（接入 Operation，扩展 Tag/Qualifier）：
```rust
impl PointcutMatcher for PointcutExpr {
    fn matches_operation(&self, operation: &Operation) -> bool {
        let func = FunctionDescriptor::from_operation(operation);  // 转换
        match self {
            PointcutExpr::Execution(p) => p.matches(&func),
            PointcutExpr::Within(p) => p.matches(&func),
            PointcutExpr::Tag(p) => p.matches_operation(operation),       // 🆕 扩展
            PointcutExpr::Qualifier(p) => p.matches_operation(operation), // 🆕 扩展
            PointcutExpr::And(l, r) => l.matches_operation(operation) && r.matches_operation(operation),
            PointcutExpr::Or(l, r) => l.matches_operation(operation) || r.matches_operation(operation),
            PointcutExpr::Not(inner) => !inner.matches_operation(operation),
        }
    }
}
```

| aspect-rs 宏 | 语义 | spring-aop 语义参照 | vernal-aop 移植 | 状态 |

### 切面异步化改造示例（caching）

```rust
// aspect-rs 原版（同步）
impl Aspect for CachingAspect {
    fn around(&self, pjp: ProceedingJoinPoint) -> Result<Box<dyn Any>, AspectError> {
        let key = format!("{}:{}", pjp.context().module_path, pjp.context().function_name);
        if let Some(cached) = self.cache.get(&key) {
            return Ok(cached);
        }
        let result = pjp.proceed()?;
        self.cache.insert(key, result.clone());
        result
    }
}

// vernal-aop 移植版（异步，实现现有 Interceptor）
#[async_trait]
impl Interceptor for CachingAspect {
    async fn intercept(&self, inv: Arc<Invocation>, next: Next) -> InvocationResult {
        let key = format!("{}:{}", inv.operation().component(), inv.operation().method());
        if let Some(cached) = self.cache.get(&key) {
            return Ok(cached);
        }
        let result = next.run().await;
        if let Ok(value) = &result {
            self.cache.insert(key, value.clone()).await;
        }
        result
    }
}
```

## 十、执行模型对比（aspect-rs vs vernal-aop vs spring-aop）

### aspect-rs 调用链（同步，逐函数织入）

```
save_user(args)                           // 原函数
  → #[aspect] 宏生成的包装函数
    → Aspect.around(ProceedingJoinPoint)
      → Aspect.before(ctx)
      → pjp.proceed()                     // 执行原函数
      → Aspect.after(ctx, result) / after_error
```

### vernal-aop 调用链（异步，预编译 + InvocationPlan）

```
AdvisedService.method(args)               // #[aspect] 宏生成
  → InvocationPlanCatalog.get(operation)  // 启动期预编译（vernal 优势）
  → InvocationPlan.execute(invocation)
    → Aspect.around(inv, next)            // 或直接 Interceptor.intercept
      → Aspect.before(inv).await
      → next.run().await                  // = ProceedingJoinPoint.proceed()
      → Aspect.after(inv, result).await / after_error
```

### spring-aop 调用链（运行时反射）

```
Proxy.method(args)                        // CGLIB/JDK 代理
  → JdkDynamicAopProxy.invoke()
    → ReflectiveMethodInvocation.proceed()
      → Advisor1 (MethodBeforeAdvice.before)
      → Advisor2 (MethodInterceptor.invoke)
        → target.method(args)
```

**三者关系**：vernal-aop 采用 **aspect-rs 的 Aspect 四段式门面** +
**自己的 InvocationPlan 预编译**（比 aspect-rs 逐函数织入更高效）+
**spring-aop 的 Advisor 链语义**（多 Advisor 组合）。这是三者优点的融合。
