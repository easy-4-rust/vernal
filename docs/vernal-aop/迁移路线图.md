# vernal-aop 全量迁移路线图

> 版本：v2.0（2026-07-27）｜**主线：aspect-rs**（aspect-core 0.1.2 + aspect-macros + aspect-std）
> 语义参考：Spring Framework **7.0.8** spring-aop（208 类）
> 仓库：easy-4-rust/vernal @ dev ｜ 本文档随代码同步维护，每阶段完成时更新
> v1.0 说明：本文档以 **aspect-rs 为实现主线**（覆盖 v1.0 的 spring-aop 主线版本），
> spring-aop 仅作语义完整度参照，不再作为结构拆分依据。

## 一、总目标

以 **aspect-rs**（Rust 原生 AOP 框架）为实现主线，把现有 vernal-aop（52 文件、
Tokio-first 异步 Around-only 内核）补齐为功能语义完全对齐的 AOP crate。
spring-aop（208 类）仅作**语义参照系**，回答"功能完整度够不够"，不作为文件拆分依据。

### 为什么选 aspect-rs 作主线

| 维度 | aspect-rs（主线）| spring-aop（语义参考）| 决策依据 |
|---|---|---|---|
| 语言范式 | Rust 原生（trait + 闭包 + 过程宏）| Java（反射 + CGLIB 字节码 + AspectJ Weaver）| aspect-rs 无语言范式转换成本 |
| Advice 模型 | `Aspect` trait（before/after/after_error/around 四段式）| 6 类（Before/After/AfterReturning/Throws/Around/Introduction）| aspect-rs 四段式已覆盖核心，Introduction 用 trait object 补 |
| Pointcut | `Pointcut` AST + `parse_pointcut` 解析器（Rust 原生）| AspectJ 表达式（依赖 Weaver）| aspect-rs 有现成 Rust 解析器，spring-aop 需自实现 |
| 织入机制 | `#[aspect]` / `#[advice]` 过程宏 | CGLIB/JDK 动态代理（运行时字节码）| Rust 无运行时字节码，过程宏是唯一正确路径 |
| 业务切面 | aspect-std 8 个生产级切面 | interceptor 包 13 个调试类切面 | aspect-std 业务价值更高 |
| 异步支持 | 同步（需改造）| Reactor Mono/Flux | vernal-aop 已有 Tokio-first，主线需异步化 |

**结论**：aspect-rs 是 **spring-aop 概念的 Rust 原生实现**，把它作为主线，
vernal-aop 只需做**异步化改造**（同步 Aspect → 异步 Interceptor）和**与现有 Operation
体系融合**两件事，避免重写整个框架。

### 与 spring-aop 的关系（语义参照）

spring-aop 208 类提供"**功能完整度标尺**"。每个迁移阶段对照 spring-aop 回答：
- "aspect-rs 的实现是否覆盖了 spring-aop 对应包的语义？"
- "若覆盖，aspect-rs 怎么改异步；若不覆盖，vernal-aop 是否需要补？"

| spring-aop 包 | 类数 | aspect-rs 对应 | 处置 |
|---|---|---|---|
| 根包（Advice/Pointcut/Advisor）| 24 | aspect-core 的 Aspect/JoinPoint/Pointcut | ✅ aspect-rs 覆盖，移植 |
| framework（Proxy 工厂）| 50 | aspect-macros 的 `#[aspect]`/`#[advice]` | 🔶 aspect-rs 用宏替代，语义等价 |
| aspectj（AspectJ 表达式）| 42 | aspect-core/pointcut/（DSL）| ✅ aspect-rs 自带 Rust 解析器 |
| support（Pointcut/Advisor 实现）| 31 | aspect-core/pointcut/（Pattern）| ✅ aspect-rs 覆盖核心 |
| target（TargetSource）| 17 | （aspect-rs 无，用 InvocationTarget 替代）| 🚫 不迁移，vernal 已有 |
| interceptor（工具切面）| 13 | aspect-std 8 个业务切面 | 🔶 互补，aspect-std 价值更高 |
| config（XML/注解配置）| 17 | （aspect-rs 无，用过程宏替代）| 🚫 不迁移 |
| scope（作用域代理）| 5 | （aspect-rs 无）| 🚫 不迁移，用 vernal-context scope |

### 设计原则

1. **aspect-rs 主线优先**：结构拆分、命名、API 设计以 aspect-rs 为准
2. **异步化是核心改造**：aspect-rs 的同步 `Aspect` → vernal-aop 异步 `Interceptor`
3. **保留 vernal-aop 现有优势**：InvocationPlan 预编译、Operation 体系、Tokio-first
4. **spring-aop 仅作语义标尺**：不照搬结构，只回答"功能够不够"
5. `#![forbid(unsafe_code)]`（与 vernal 全 workspace 一致）
6. **每个 .rs 文件只对应一个 aspect-rs 对象**（与 vernal-expression 一致）

## 三、阶段详细计划

### S1 — aspect-core 移植（P0，预估 4 天）

**范围**：aspect-rs/aspect-core 全部 9 个源文件，异步化改造

**核心改造**：aspect-rs 是同步模型，vernal-aop 是 Tokio-first 异步。
S1 把 aspect-core 的同步抽象移植并改造为异步。

#### S1.1 JoinPoint 体系（2 文件，0.5 天）

| 目标文件 | aspect-rs 源 | 改造点 | spring-aop 语义参照 |
|---|---|---|---|
| `joinpoint.rs`（🆕 或合并到现有 operation.rs）| `joinpoint.rs::JoinPoint` | 不单独移植，**复用现有 `Operation`**（component/method 是 function_name/module_path 的超集）| `JoinPoint` / `MethodInvocation` |
| `proceeding_joinpoint.rs`（🆕 或合并到 next.rs）| `joinpoint.rs::ProceedingJoinPoint` | 不单独移植，**复用现有 `Next`**（`run().await` 等价 `proceed()`）| `ProceedingJoinPoint.proceed()` |

**决策**：aspect-rs 的 `JoinPoint`/`ProceedingJoinPoint` 与 vernal-aop 现有
`Operation`/`Next` **语义等价且 vernal 版本更强**（Operation 含 tags/qualifier，
Next 是异步）。**不新增文件**，仅在文档记录映射关系。

#### S1.2 Aspect trait 异步化（1 文件，1 天）⭐ 核心

| 目标文件 | aspect-rs 源 | 改造点 | spring-aop 语义参照 |
|---|---|---|---|
| `aspect.rs`（🆕）| `aspect.rs::Aspect` trait | **同步 → 异步**：before/after/after_error 改返回 `BoxFuture`，around 签名改为 `(Arc<Invocation>, Next) -> InvocationFuture` | `MethodBeforeAdvice`/`AfterReturningAdvice`/`ThrowsAdvice`/`MethodInterceptor` |

**aspect-rs 原版**（同步）：
```rust
pub trait Aspect: Send + Sync {
    fn before(&self, ctx: &JoinPoint) {}
    fn after(&self, ctx: &JoinPoint, result: &dyn Any) {}
    fn after_error(&self, ctx: &JoinPoint, error: &AspectError) {}
    fn around(&self, pjp: ProceedingJoinPoint) -> Result<Box<dyn Any>, AspectError> {
        // 默认实现：before → proceed → after/after_error
    }
}
```

**vernal-aop 移植版**（异步）：
```rust
#[async_trait]
pub trait Aspect: Send + Sync + 'static {
    async fn before(&self, inv: &Invocation) -> Result<(), InvocationError> { Ok(()) }
    async fn after(&self, inv: &Invocation, result: &InvocationValue) { }
    async fn after_error(&self, inv: &Invocation, error: &InvocationError) { }
    async fn around(&self, inv: Arc<Invocation>, next: Next) -> InvocationResult {
        // 默认实现保留 aspect-rs 的 before→proceed→after 模式（异步化）
        self.before(&inv).await?;
        let result = next.run().await;
        match &result {
            Ok(v) => self.after(&inv, v).await,
            Err(e) => self.after_error(&inv, e).await,
        }
        result
    }
}
```

**与现有 Interceptor 的关系**：现有 `Interceptor`（Around-only）保留为**底层执行原语**，
新增 `Aspect` trait 作为**用户友好门面**（四段式）。提供 `AspectAdapter` 把 `Aspect`
自动适配为 `Interceptor`。

#### S1.3 Pointcut DSL 移植（5 文件，2 天）⭐ 最大价值

| 目标文件 | aspect-rs 源 | 改造点 | spring-aop 语义参照 |
|---|---|---|---|
| `pointcut/dsl/mod.rs` | `pointcut/mod.rs` | 模块声明 | — |
| `pointcut/dsl/ast.rs` | `pointcut/ast.rs::Pointcut` enum | **改名 `PointcutExpr`**（避免与现有 `Pointcut` trait 冲突）+ 扩展 `Tag`/`Qualifier` 变体 | AspectJ 表达式 AST |
| `pointcut/dsl/pattern.rs` | `pointcut/pattern.rs`（4 类）| **直接移植** `Visibility`/`NamePattern`/`ExecutionPattern`/`ModulePattern` | `ClassFilter`/`MethodMatcher` |
| `pointcut/dsl/matcher.rs` | `pointcut/matcher.rs`（`Matcher`/`FunctionInfo`）| **改名** `PointcutMatcher`/`FunctionDescriptor`，matches 改为接收 vernal `Operation` | `MethodMatcher` |
| `pointcut/dsl/parser.rs` | `pointcut/parser.rs::parse_pointcut` | **改名** `parse_pointcut_expr`，扩展 `tag()`/`qualifier()` 语法 | AspectJ Weaver 解析器 |

**核心价值**：spring-aop 的 AspectJ 表达式依赖 Weaver（🚫 无法迁移），
aspect-rs 已有 Rust 原生解析器，直接移植省去自实现（预估节省 4 天）。

#### S1.4 错误体系（1 文件，0.5 天）

| 目标文件 | aspect-rs 源 | 改造点 | spring-aop 语义参照 |
|---|---|---|---|
| `aspect_error.rs`（🆕 或扩展现有 invocation_error.rs）| `error.rs::AspectError` | 移植 3 变体（ExecutionError/WeavingError/Custom），适配 thiserror | `AopInvocationException` |

**验收**：`PointcutExpr::parse("execution(pub fn save_*(..)) && within(crate::api)")`
能解析并匹配 vernal Operation；`Aspect` trait 四段式异步默认实现工作；
`AspectAdapter` 能把 `Aspect` 转为现有 `Interceptor`。

### S2 — aspect-macros 移植（P0，预估 2 天）

**范围**：aspect-rs/aspect-macros 5 文件 → vernal-macros crate 新增

| 目标文件 | aspect-rs 源 | 改造点 | spring-aop 语义参照 |
|---|---|---|---|
| `vernal-macros/src/aspect_macro.rs`（🆕）| `aspect_attr.rs` + `lib.rs::#[aspect]` | 移植 `#[aspect(LoggingAspect)]`，生成异步包装代码 | CGLIB 代理生成 |
| `vernal-macros/src/advice_macro.rs`（🆕）| `advice_macro.rs` + `lib.rs::#[advice]` | 移植 `#[advice(pointcut=..., advice=..., order=...)]`，扩展 5 类 advice | `@Aspect`/`@Pointcut` 注解 |
| `vernal-macros/src/advice_args.rs`（🆕）| `AdviceArgs` | 参数结构，扩展 advice 类型枚举 | — |

**用法对比**：

```rust
// aspect-rs 原版（同步）
#[aspect(LoggingAspect)]
fn save_user(user: User) -> Result<User> { ... }

#[advice(pointcut = "execution(pub fn *(..))", advice = "around", order = 10)]
fn log_around(pjp: ProceedingJoinPoint) -> Result<Box<dyn Any>, AspectError> { ... }

// vernal-aop 移植版（异步）
#[aspect(LoggingAspect)]
async fn save_user(user: User) -> Result<User> { ... }

#[advice(
    pointcut = "execution(pub fn *(..)) && within(crate::api) || tag(secured)",
    advice = "around",  // 支持 before/after/after_error/around
    order = 10
)]
async fn log_around(inv: Arc<Invocation>, next: Next) -> InvocationResult { ... }
```

**与现有 InvocationPlan 的融合（S4）**：`#[advice]` 宏在编译期生成注册代码，
启动时填入 `InvocationPlanCatalog`（vernal-aop 现有预编译目录）。

**验收**：`#[aspect]` 宏能包装函数为带 Aspect 调用链的异步函数；
`#[advice]` 宏能注册到 InvocationPlanCatalog；trybuild 覆盖编译期负例。

## 四、工程规范

### 命名规则

| 项目 | 规范 | 示例 |
|------|------|------|
| 目录/文件名 | snake_case | `pointcut/dsl/ast.rs`、`interceptor/caching_aspect.rs` |
| 类型名 | PascalCase | `Aspect`、`PointcutExpr`、`CachingAspect` |
| 方法名 | snake_case | `before`、`after_returning`、`around` |
| 业务切面后缀 | `_aspect` | `logging_aspect.rs`（与 aspect-std 一致）|

### 命名冲突规避（关键）

| aspect-rs 原名 | vernal-aop 移植名 | 冲突原因 |
|---|---|---|
| `Pointcut`（AST enum）| `PointcutExpr` | 与现有 `Pointcut` trait 冲突 |
| `Matcher` trait | `PointcutMatcher` | 避免歧义 |
| `FunctionInfo` | `FunctionDescriptor` | 与 `Operation` 概念混淆 |
| `parse_pointcut` | `parse_pointcut_expr` | 强调解析表达式 |
| `Aspect` trait | 保留原名 `Aspect` | 与现有 `Interceptor` 共存（Aspect 是用户门面，Interceptor 是底层原语）|

### 文件结构规范

```rust
//! 对应 aspect-rs：aspect-core/src/aspect.rs::Aspect
//! 语义参照 spring-aop：MethodBeforeAdvice / AfterReturningAdvice / ThrowsAdvice / MethodInterceptor
//!
//! 切面门面 trait（四段式异步通知）。
//! 移植自 aspect-rs 的 Aspect trait，改造为 Tokio-first 异步。

use std::sync::Arc;
use crate::{Invocation, InvocationError, InvocationResult, InvocationValue, Next};

/// 切面门面（四段式异步通知）。
///
/// 对应 aspect-rs 的 `Aspect` trait，before/after/after_error/around 四段式
/// 改造为异步。`around` 默认实现保留 aspect-rs 的 before→proceed→after 模式。
///
/// 与现有 `Interceptor` 的关系：`Aspect` 是用户友好门面，`Interceptor` 是
/// 底层执行原语。通过 `AspectAdapter` 自动转换。
#[async_trait]
pub trait Aspect: Send + Sync + 'static {
    /// 方法执行前调用（异步）。
    async fn before(&self, _inv: &Invocation) -> Result<(), InvocationError> { Ok(()) }
    // ...
}
```

### 测试规范

- 每个移植类型至少 1 个测试（复用 aspect-rs 测试用例）
- 异步测试用 `#[tokio::test]`
- 过程宏必须有 trybuild 编译期负例
- 业务切面用真实 crate（moka/governor/failsafe）验证

## 五、风险评估

| 风险 | 影响 | 对策 |
|------|------|------|
| aspect-rs 是实验性项目（0.1.2）| API 可能不稳定 | 移植核心类型到 vernal-aop，不直接依赖 aspect-rs crate |
| 同步→异步改造工作量 | S1/S3 可能超时 | 先移植数据类型（Pointcut DSL 无需异步化），再改造 trait |
| `Pointcut` 名称冲突 | 编译错误 | 统一改名 `PointcutExpr`，文档明确 |
| aspect-std 依赖外部 crate（moka/failsafe）| 依赖体积 | feature flag，默认不启用业务切面 |
| `#[aspect]` 宏与现有 InvocationPlan 冲突 | 双重织入 | S4 阶段明确：宏生成代码注册到 InvocationPlanCatalog，不绕过 |
| spring-aop 语义补缺（Introduction）| Rust 无运行时 trait impl | 用 trait object + Any downcast 替代 |
