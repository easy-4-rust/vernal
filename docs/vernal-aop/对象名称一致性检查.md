## 二、名称冲突需改名的 5 个对象（关键）

以下 aspect-rs 对象与 vernal-aop 现有类型**同名或语义冲突**，移植时**必须改名**：

| aspect-rs 原名 | 冲突对象 | vernal-aop 移植名 | 冲突原因 | 处理 |
|---|---|---|---|---|
| `Pointcut`（AST enum）| 现有 `Pointcut` trait（基于 Operation）| **`PointcutExpr`** | 名称直接冲突 | 改名避免歧义 |
| `Matcher` trait | （潜在歧义）| **`PointcutMatcher`** | 避免与未来类型冲突 | 改名 |
| `FunctionInfo` struct | 与 `Operation` 概念混淆 | **`FunctionDescriptor`** | 语义重叠 | 改名 |
| `parse_pointcut` 函数 | 与 `Pointcut::parse` 关联 | **`parse_pointcut_expr`** | 强调解析表达式 | 改名 |
| `proceed` 方法 | 现有 `Next::run` | **不移植，用 `run`** | Next 已等价 | 🚫 不移植 |

### 改名详细理由

#### 1. `Pointcut` → `PointcutExpr`（最关键）

```
vernal-aop 现有（保留）：
  pub trait Pointcut { fn matches(&self, operation: &Operation) -> bool; }
  （8 个实现：AndPointcut/OrPointcut/NotPointcut/AnyPointcut/MethodPointcut/...）

aspect-rs（移植）：
  pub enum Pointcut { Execution(...), Within(...), And(...), Or(...), Not(...) }

冲突：两者都叫 Pointcut，但一个是 trait（运行期匹配），一个是 enum（AST 节点）
解决：aspect-rs 的 enum 改名为 PointcutExpr（表达式 AST），与现有 Pointcut trait 共存
      现有 8 个 Pointcut 实现保留，新增 PointcutExpr 作为 DSL 解析产物
```

#### 2. `Matcher` → `PointcutMatcher`

```
aspect-rs：pub trait Matcher { fn matches(&self, function: &FunctionInfo) -> bool; }
冲突：未来 vernal-aop 可能有其他 Matcher（如 AOP Matcher / Non-AOP Matcher）
解决：改名 PointcutMatcher，明确职责是 Pointcut 匹配
      方法名改为 matches_operation（接收 vernal Operation，而非 FunctionInfo）
```

#### 3. `FunctionInfo` → `FunctionDescriptor`

```
aspect-rs：pub struct FunctionInfo { name, module_path, visibility, return_type }
vernal-aop：pub struct Operation { component, method, metadata }
冲突：FunctionInfo 与 Operation 都是"函数信息"，容易混淆
解决：FunctionInfo 改名 FunctionDescriptor，作为 Pointcut 匹配用的中间结构，
      从 Operation 转换而来（FunctionDescriptor::from_operation）
```

#### 4. `parse_pointcut` → `parse_pointcut_expr`

```
aspect-rs：pub fn parse_pointcut(input: &str) -> Result<Pointcut, String>
冲突：函数返回 Pointcut（已改名 PointcutExpr），函数名需对应
解决：改名 parse_pointcut_expr，错误类型从 String 改为 PointcutParseError
```

#### 5. `proceed` → 不移植（用现有 `run`）

```
aspect-rs：ProceedingJoinPoint::proceed(self) -> Result<Box<dyn Any>, AspectError>
vernal-aop：Next::run(self) -> InvocationResult（异步 .await）
冲突：proceed 是同步消费方法，run 是异步消费方法，语义等价但形态不同
解决：不移植 ProceedingJoinPoint，复用现有 Next；Aspect::around 的 next 参数用 Next
```

## 七、业务逻辑一致性检查

### ✅ 将完全一致的逻辑（移植后）

- Pointcut DSL 表达式解析（`execution` / `within` / `&&` / `||` / `!`）
- Pattern 匹配（`Wildcard` / `Exact` / `Prefix` / `Suffix` / `Contains`）
- Visibility 匹配（`Public` / `Crate` / `Super` / `Private`）
- ModulePattern 的前缀匹配（含 `::`）
- Aspect trait 四段式通知（before/after/after_error/around）
- around 默认实现模式（before → proceed → after/after_error）
- 8 个业务切面的核心语义（caching/ratelimit/circuitbreaker 等）

### ⚠️ 形态不同但语义等价的逻辑（异步化改造）

- `Aspect::around`（同步）→ `Aspect::around`（异步 `.await`）
- `ProceedingJoinPoint::proceed()`（同步）→ `Next::run().await`（异步）
- `AspectError`（同步错误）→ `AspectError`（移植）+ `InvocationError`（现有异步错误）
- aspect-std 切面的同步 `impl Aspect` → 异步 `impl Interceptor`
- `Aspect::before/after/after_error`（同步 void）→ 异步返回 `BoxFuture`

### ❌ 不移植的逻辑

- `JoinPoint` / `ProceedingJoinPoint`（用现有 Operation/Next 替代）
- `#[aspect]` 的逐函数织入（用 InvocationPlanCatalog 预编译替代）
- aspect-runtime / aspect-driver 的 rustc 织入（用过程宏替代）

### 🆕 vernal-aop 扩展的逻辑（无 aspect-rs 对偶）

- `tag(name)` / `qualifier(name)` Pointcut 语法
- `PointcutExpr::Tag` / `PointcutExpr::Qualifier` AST 节点
- `FunctionDescriptor` 的 `tags` / `qualifier` 字段
- `#[advice]` 宏的 4 类 advice（aspect-rs 仅 around，扩展为 before/after/after_error/around）
- `AspectAdapter`（Aspect → Interceptor 自动桥接）
- `IntroductionInfo` / `IntroductionAdvisor`（S5，spring-aop 概念）

## 八、命名规范总结（吸收 aspect-rs 后的最终规则）

| 规则 | 说明 | 示例 |
|---|---|---|
| Aspect trait 保留原名 | 与 aspect-rs 一致，作为用户门面 | `Aspect::before/after/after_error/around` |
| Interceptor 保留原名 | 现有底层原语，与 Aspect 共存 | `Interceptor::intercept` |
| Pointcut trait 保留原名 | 现有运行期匹配 trait | `AndPointcut` / `TagPointcut` |
| Pointcut AST 改名 `PointcutExpr` | 避免与 trait 冲突 | `PointcutExpr::Execution(...)` |
| Pattern 类型保留原名 | 无冲突，直接移植 | `Visibility` / `NamePattern` |
| Matcher 改名 `PointcutMatcher` | 明确职责 | `PointcutMatcher::matches_operation` |
| FunctionInfo 改名 `FunctionDescriptor` | 避免与 Operation 混淆 | `FunctionDescriptor::from_operation` |
| 业务切面用 `_aspect` 后缀 | 与 aspect-std 一致 | `caching_aspect.rs` |
| `#[aspect]` / `#[advice]` 宏保留原名 | 与 aspect-rs 一致 | `#[aspect(LoggingAspect)]` |
| AspectError 保留原名 | 与 aspect-rs 一致 | `AspectError::ExecutionError` |

## 十、结论

| 维度 | 结果 |
|------|------|
| 名称完全一致（直接移植）| **15/23 = 65.2%** |
| 名称冲突需改名 | **5/23 = 21.7%**（Pointcut/Matcher/FunctionInfo/parse_pointcut/proceed）|
| 不移植（已有等价物）| **2/23 = 8.7%**（JoinPoint/ProceedingJoinPoint）|
| vernal-aop 扩展 | **7 个**（Tag/Qualifier DSL + AspectAdapter + Introduction 等）|
| 核心冲突解决 | `Pointcut` enum → `PointcutExpr`（最关键）|
| 与现有 52 文件冲突 | 仅 1 处（Pointcut），已解决 |

### 关键发现

1. **aspect-rs 的 Pattern 体系（4 类）零冲突直接移植**——`Visibility`/`NamePattern`/
   `ExecutionPattern`/`ModulePattern` 名称与 vernal-aop 无冲突
2. **aspect-rs 的 aspect-std 8 个切面零冲突直接移植**——只需异步化改造
3. **aspect-rs 的 `Aspect` trait / `AspectError` / 宏名零冲突**——保留原名
4. **唯一硬冲突是 `Pointcut`**——aspect-rs 的 enum 与 vernal-aop 的 trait 同名，
   改名 `PointcutExpr` 解决
5. **`JoinPoint`/`ProceedingJoinPoint` 不移植**——用现有 `Operation`/`Next` 替代（更强）

### 主线决策的命名收益

采用 aspect-rs 主线后，vernal-aop 的命名**与 aspect-rs 高度一致**（65.2% 完全匹配），
Spring 用户和 aspect-rs 用户都能快速上手。仅有的 5 处改名都有明确理由（避免冲突/明确职责），
不引入认知负担。相比 v1.0（spring-aop 主线，需自创大量命名），v2.0 的命名一致性显著提升。
