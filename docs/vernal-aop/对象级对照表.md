#### 命名与组织规则

1. 目录、文件名一律 snake_case；类型 PascalCase；方法 snake_case
2. **每个 .rs 文件只对应一个 aspect-rs 对象**（或一组紧密相关的 trait）
3. `mod.rs` 只做模块声明与 re-export，**禁止定义任何类型/逻辑**
4. 业务切面用 `_aspect` 后缀（与 aspect-std 一致），区别于现有 `simple_interceptor`
5. 每个文件头部中文 doc 注释：说明对应 aspect-rs 源 + spring-aop 语义参照

##### Java 注解 → Rust 宏的映射规则

Java 的 `@Annotation` 在 Rust 中用 **derive macro** 或 **attribute macro** 替代，根据职责选择：

| Java 注解类型 | Rust 宏类型 | 放置位置 | 示例 |
|---|---|---|---|
| 数据型注解（Lombok @Data 等）| derive macro | 模块内 `advice/` 目录 | `#[derive(Component)]` |
| 行为型注解（@Aspect @Transactional 等）| attribute macro | 模块内 `advice/` 目录 | `#[aspect]` / `#[advice]` |
| 配置型注解（@Value @ConfigurationProperties）| derive macro | 模块内 `advice/` 目录 | `#[derive(ConfigurationProperties)]` |

**放置原则**：Spring 的注解分散在各个模块中（`@Transactional` 在 spring-tx，
`@Cacheable` 在 spring-cache 等），Rust 迁移时宏也应在各自模块中：
- 每个模块创建 `advice/` 目录，存放该模块的 derive macro 或 attribute macro
- vernal-aop 的 `#[aspect]` / `#[advice]` → `vernal-aop/src/advice/`
- vernal-tx 的 `#[transactional]` → `vernal-tx/src/advice/`
- 共用的基础宏（如 `#[derive(Component)]`）→ `vernal-macros`（公共 crate）

**aspect-rs 原版**（同步）：
```rust
pub trait Aspect: Send + Sync {
    fn before(&self, ctx: &JoinPoint) {}
    fn after(&self, ctx: &JoinPoint, result: &dyn Any) {}
    fn after_error(&self, ctx: &JoinPoint, error: &AspectError) {}
    fn around(&self, pjp: ProceedingJoinPoint) -> Result<Box<dyn Any>, AspectError> { ... }
}
```

**vernal-aop 移植版**（异步）：
```rust
#[async_trait]
pub trait Aspect: Send + Sync + 'static {
    async fn before(&self, inv: &Invocation) -> Result<(), InvocationError> { Ok(()) }
    async fn after(&self, inv: &Invocation, result: &InvocationValue) {}
    async fn after_error(&self, inv: &Invocation, error: &InvocationError) {}
    async fn around(&self, inv: Arc<Invocation>, next: Next) -> InvocationResult { ... }
}
```

##### 1.2 JoinPoint 体系（joinpoint.rs，3 类 → 🔶 复用现有）

| aspect-rs 类 | 目标 | 状态 | spring-aop 语义参照 | 决策 |

| `JoinPoint`（function_name/module_path/location）| 复用现有 `Operation` | 🔶 不移植 | `JoinPoint`/`MethodInvocation` | Operation（component/method/metadata）是超集 |
| `Location`（file/line 静态位置）| 复用现有 `OperationMetadata` | 🔶 不移植 | （静态位置）| 可选加入 metadata |

**决策**：aspect-rs 这 3 个类与 vernal-aop 现有 `Operation`/`Next` **语义等价且 vernal 版本更强**
（Operation 含 tags/qualifier，Next 是异步）。**不新增文件**，仅在文档记录映射。

| `Visibility` enum | Public/Crate/Super/Private | ✅ 保留（matches 方法保留）|
| `NamePattern` enum | Wildcard/Exact/Prefix/Suffix/Contains | ✅ 保留 |
| `ExecutionPattern` struct | visibility: Option<Visibility>, name: NamePattern, return_type: Option<String> | ✅ 保留 |
| `ModulePattern` struct | path: String | ✅ 保留（matches_path 保留）|

| aspect-rs 方法 | vernal-aop 移植 |

> vernal-aop 的宏放在 `vernal-aop/src/advice/`，而非集中到 `vernal-macros`。

| aspect-rs 文件 | 目标文件 | 状态 | spring-aop 语义参照 | 说明 |
|---|---|---|---|---|
| `lib.rs`（`#[aspect]` + `#[advice]`）| `vernal-aop/src/advice/mod.rs` | 🆕 ⬜ S2 | CGLIB/JDK 代理生成 | 两个宏入口 |
| `aspect_attr.rs`（`#[aspect]` 转换）| `vernal-aop/src/advice/aspect_macro.rs` | 🆕 ⬜ S2 | `AbstractAdvisingBeanPostProcessor` | 移植并异步化 |
| `advice_macro.rs`（`AdviceArgs` + transform）| `vernal-aop/src/advice/advice_macro.rs` | 🆕 ⬜ S2 | `@Aspect`/`@Pointcut`/`@Around` 宏（Java 注解的 Rust 对等）| 移植并扩展 5 类 advice |

| `codegen.rs`（TokenStream 生成）| 合并入 `aspect_macro.rs` / `advice_macro.rs` | 🔀 ⬜ S2 | — | 合并 |

#### 附录：aspect-rs 与 spring-aop 概念映射（语义参照）

下表展示 aspect-rs 主线如何覆盖 spring-aop 语义：

| 概念 | spring-aop（语义参考）| aspect-rs（实现主线）| vernal-aop 最终形态 |
|---|---|---|---|
| 切点表达式 | AspectJ 表达式（execution/within/args/this/target）| 🎯 `Pointcut` AST（execution/within + &&/\|\|/!）| `PointcutExpr` + 扩展 tag/qualifier |
| 前置通知 | `MethodBeforeAdvice.before()` | `Aspect::before()` | `Aspect::before()`（异步）|
| 后置通知 | `AfterReturningAdvice.afterReturning()` | `Aspect::after()` | `Aspect::after()`（异步）|
| 异常通知 | `ThrowsAdvice`（反射）| `Aspect::after_error()` | `Aspect::after_error()`（异步）|
| 环绕通知 | `MethodInterceptor.invoke()` | `Aspect::around()` | `Aspect::around()` + 现有 `Interceptor`（异步）|
| 引入 | `IntroductionAdvisor` | （无）| S5 补 `IntroductionAdvisor` |
| 切点匹配 | `MethodMatcher` | `Matcher` trait | `PointcutMatcher`（改名）|
| 函数信息 | `Method`（反射）| `FunctionInfo` | `FunctionDescriptor`（改名）|
| 声明式绑定 | `@Aspect` + `@Pointcut` 注解 | 🎯 `#[aspect]` / `#[advice]` attribute macro | 移植 2 个宏 |
| 业务切面 | interceptor 包 13 类（调试）| 🎯 aspect-std 8 类（生产）| 移植 aspect-std |
| 代理工厂 | ProxyFactory + CGLIB/JDK | 🎯 `#[aspect]` 过程宏 | 移植宏 |
| 错误 | `AopInvocationException` | `AspectError` | `AspectError`（移植）+ 现有 InvocationError |

**核心结论**：aspect-rs 作为 Rust 原生主线，覆盖 spring-aop **80% 核心语义**，
剩余 20%（Introduction / 部分 Pointcut designator）在 S5 补齐，总工作量 ~14 天
（比 spring-aop 主线的 24.5 天节省 10.5 天）。
