# aspect-rs → vernal-aop 功能语义迁移对照表（参考蓝本）

基线：aspect-rs @ main（aspect-core 0.1.2 + aspect-macros + aspect-std）
本表回答"**功能语义对不对齐**"，与 `对象级对照表.md`（回答"对象落在哪个文件"）互补。

迁移原则：**Rust 原生优先**。aspect-rs 本身是 Rust 实现，移植时无需语言范式转换，
重点在**异步化改造**（同步 → Tokio-first）和**命名冲突规避**（Pointcut → PointcutExpr 等）。

状态图例：✅ 已移植并有测试 / 🔀 语义已移植待改造 / 🔶 语义等价但形态不同（仅参考）/
⬜ 待移植（A1/A2/A3 路线图）/ 🚫 不移植（已有等价物）/ 🆕 vernal-aop 侧扩展

## 一、Aspect 通知体系（4 类 → 不移植，仅参考）

aspect-rs 的 `Aspect` trait 定义了 **before/after/after_error/around** 四段式同步通知，
vernal-aop 已有**异步 Around**（`Interceptor` trait），S1 阶段基于 spring-aop 补齐
Before/After/Throws 三类。aspect-rs 在此**仅作形态参考**，不直接移植。

| aspect-rs 方法 | 语义 | Rust 实现（vernal-aop）| 状态 |
|---|---|---|---|
| `Aspect::before(&self, ctx: &JoinPoint)` | 方法执行前调用 | S1 新增 `MethodBeforeAdvice::before(&Invocation)` | 🔶 参考 |
| `Aspect::after(&self, ctx: &JoinPoint, result: &dyn Any)` | 方法成功后调用 | S1 新增 `AfterReturningAdvice::after_returning(&Invocation, &InvocationValue)` | 🔶 参考 |
| `Aspect::after_error(&self, ctx: &JoinPoint, error: &AspectError)` | 方法异常时调用 | S1 新增 `ThrowsAdvice::after_throwing(&Invocation, &InvocationError)` | 🔶 参考 |
| `Aspect::around(&self, pjp: ProceedingJoinPoint) -> Result<Box<dyn Any>, AspectError>` | 包裹整个执行 | 现有 `Interceptor::intercept(Arc<Invocation>, Next) -> InvocationFuture` | 🔶 形态不同（同步→异步）|

### Advice 语义对比（aspect-rs vs vernal-aop S1 目标）

| 语义点 | aspect-rs | vernal-aop S1 目标 |
|---|---|---|
| 返回值类型 | `Result<Box<dyn Any>, AspectError>`（Box 动态分发）| `InvocationFuture`（async，强类型）|
| 执行控制 | `ProceedingJoinPoint::proceed()`（同步）| `Next::run()`（异步 `.await`）|
| 上下文 | `JoinPoint`（function_name/module_path/location）| `Invocation`（operation/context/cancellation/deadline）|
| 线程安全 | `Aspect: Send + Sync` | `Interceptor: Send + Sync + 'static` |
| 默认实现 | `around` 默认调用 before→proceed→after/after_error | vernal-aop 不提供默认 around（强制用户显式实现）|

### Aspect trait 默认实现的参考价值

aspect-rs 的 `around` 默认实现：
```rust
fn around(&self, pjp: ProceedingJoinPoint) -> Result<Box<dyn Any>, AspectError> {
    let ctx = pjp.context().clone();
    self.before(&ctx);              // 先 before
    let result = pjp.proceed();     // 执行
    match &result {
        Ok(value) => self.after(&ctx, value.as_ref()),        // 成功 after
        Err(error) => self.after_error(&ctx, error),          // 失败 after_error
    }
    result
}
```

**vernal-aop 的 `advice_adapter`（S1 新增）可借鉴此模式**，把 Before/After/Throws
三类同步 Advice 自动包装为异步 Around Interceptor：
```rust
// vernal-aop 的 advice_adapter（异步版）
async fn adapt_around(inv: Arc<Invocation>, next: Next, advice: Arc<dyn CombinedAdvice>) -> InvocationFuture {
    advice.before(&inv)?;                          // before 失败则短路
    let result = next.run().await;                 // 执行
    match &result {
        Ok(value) => advice.after_returning(&inv, value),
        Err(error) => advice.after_throwing(&inv, error),
    }
    result
}
```

## 二、JoinPoint 体系（3 类 → 不移植，用现有等价物）

| aspect-rs 类型 | 语义 | vernal-aop 现有等价 | 状态 |
|---|---|---|---|
| `JoinPoint`（function_name/module_path/location）| 静态连接点 | `Operation`（component/method/metadata）| 🔶 Operation 更通用 |
| `Location`（file:line）| 源码位置 | （可加入 OperationMetadata）| 🔶 可选扩展 |
| `ProceedingJoinPoint`（proceed 控制）| around 的执行控制 | `Next`（run().await）| 🔶 已等价 |

### JoinPoint 语义对比

| 字段/方法 | aspect-rs `JoinPoint` | vernal-aop `Operation` |
|---|---|---|
| 函数名 | `function_name: &'static str` | `method: Arc<str>` |
| 模块路径 | `module_path: &'static str` | `component: Arc<str>` |
| 源码位置 | `location: Location`（file/line）| （无，可扩展 metadata）|
| 元数据 | （无）| `metadata: OperationMetadata`（tags/qualifier）|
| 全限定名 | `qualified_name() -> String` | `Display for Operation`（`component::method`）|

**结论**：`Operation` 是 `JoinPoint` 的超集（多了 tags/qualifier），无需移植 `JoinPoint`。

### ProceedingJoinPoint vs Next

| 行为 | aspect-rs `ProceedingJoinPoint` | vernal-aop `Next` |
|---|---|---|
| 执行原始函数 | `pjp.proceed() -> Result<Box<dyn Any>, AspectError>`（同步）| `next.run().await -> InvocationResult`（异步）|
| 获取上下文 | `pjp.context() -> &JoinPoint` | `invocation.operation() -> &Operation`（通过 Invocation 参数获取）|
| 消费性 | `proceed(self)`（消费 pjp）| `run(self)`（消费 next）|

**结论**：`Next` 是 `ProceedingJoinPoint` 的异步等价物，无需移植。

## 三、Pointcut DSL 体系（5 文件 → A1 全部移植）⭐ 核心价值

这是 aspect-rs 对 vernal-aop **最大的价值**。spring-aop 的 AspectJ 表达式依赖
AspectJ Weaver（🚫 不迁移），vernal-aop 规划 S4 阶段自实现解析器（5 天）。
**aspect-rs 已有现成的 Rust 原生 Pointcut DSL，直接移植可将工作量降到 1 天**。

### 3.4 Matcher（pointcut/matcher.rs）

| aspect-rs 类型 | 语义 | vernal-aop 移植 | 状态 |
|---|---|---|---|
| `Matcher` trait | `matches(&FunctionInfo) -> bool` | `PointcutMatcher`（`matches_operation(&Operation)`）| ⬜ A1 改造 |
| `FunctionInfo` | 函数信息（name/module_path/visibility/return_type）| `FunctionDescriptor`（+ tags/qualifier）| ⬜ A1 改造 |

#### Matcher 实现语义（移植）

aspect-rs 为 `Pointcut` / `ExecutionPattern` / `ModulePattern` 都实现了 `Matcher`：

```rust
impl Matcher for Pointcut {
    fn matches(&self, function: &FunctionInfo) -> bool {
        match self {
            Pointcut::Execution(p) => p.matches(function),
            Pointcut::Within(p) => p.matches(function),
            Pointcut::And(l, r) => l.matches(function) && r.matches(function),
            Pointcut::Or(l, r) => l.matches(function) || r.matches(function),
            Pointcut::Not(inner) => !inner.matches(function),
        }
    }
}
```

**vernal-aop 移植版**（接入 Operation）：
```rust
impl PointcutMatcher for PointcutExpr {
    fn matches_operation(&self, operation: &Operation) -> bool {
        // 从 Operation 构造 FunctionDescriptor（含 tags/qualifier）
        let func = FunctionDescriptor::from_operation(operation);
        match self {
            PointcutExpr::Execution(p) => p.matches(&func),
            PointcutExpr::Within(p) => p.matches(&func),
            PointcutExpr::Tag(p) => p.matches_operation(operation),   // 🆕 扩展
            PointcutExpr::Qualifier(p) => p.matches_operation(operation), // 🆕 扩展
            PointcutExpr::And(l, r) => l.matches_operation(operation) && r.matches_operation(operation),
            PointcutExpr::Or(l, r) => l.matches_operation(operation) || r.matches_operation(operation),
            PointcutExpr::Not(inner) => !inner.matches_operation(operation),
        }
    }
}
```

## 四、过程宏体系（2 宏 → A2 移植 1 个）

### 4.1 `#[aspect]` 宏（不移植）

| aspect-rs 宏 | 语义 | vernal-aop | 状态 |
|---|---|---|---|
| `#[aspect(Logger)]` | 把 Aspect 实例绑定到单个函数 | `InvocationPlanCatalog` 预编译 + `#[advised]` 宏 | 🚫 |

**不移植原因**：aspect-rs 的 `#[aspect]` 是**逐函数织入**（每个函数生成包装代码），
vernal-aop 用 `InvocationPlanCatalog` **启动期预编译调用计划**，运行期零开销，
比 aspect-rs 的逐函数织入更高效。vernal-aop 提供 `#[advised]`（结构体级，S7）
替代 aspect-rs 的 `#[aspect]`（函数级）。

### 4.2 `#[advice]` 宏（A2 移植）⭐ 高价值

| aspect-rs 宏 | 语义 | vernal-aop 移植 | 状态 |
|---|---|---|---|
| `#[advice(pointcut=..., advice=..., order=...)]` | 声明式 advice 函数 | `vernal-macros::#[advice]`（异步版）| ⬜ A2 |

#### AdviceArgs 参数对比

| 参数 | aspect-rs 类型 | vernal-aop 类型 | 改造 |
|---|---|---|---|
| `pointcut` | `String`（表达式）| `String`（表达式）| 扩展支持 `tag`/`qualifier` 语法 |
| `advice` | `String`（仅 `"around"`）| `AdviceKind` enum（5 类）| **扩展**为 before/after/after_returning/after_throwing/around |
| `order` | `i32`（默认 0）| `i32`（默认 0）| ✅ 保留 |

#### 用法对比

```rust
// aspect-rs 原版（同步，仅 around）
#[advice(
    pointcut = "execution(pub fn *(..)) && within(crate::api)",
    advice = "around",
    order = 10
)]
fn log_advice(pjp: ProceedingJoinPoint) -> Result<Box<dyn Any>, AspectError> {
    println!("before: {}", pjp.context().function_name);
    let result = pjp.proceed()?;
    println!("after");
    result
}

// vernal-aop 移植版（异步，5 类 advice）
#[advice(
    pointcut = "execution(pub fn *(..)) && within(crate::api) || tag(secured)",
    advice = "around",  // 或 "before" / "after_returning" / "after_throwing"
    order = 10
)]
async fn log_advice(inv: Arc<Invocation>, next: Next) -> InvocationFuture {
    println!("before: {}", inv.operation());
    let result = next.run().await;
    println!("after");
    result
}
```

### 切面语义对齐（aspect-std → vernal-aop 异步化）

每个 aspect-std 切面都实现 `Aspect` trait（同步），移植到 vernal-aop 时改为实现
`Interceptor` trait（异步 Around）：

```rust
// aspect-std 原版（同步）
impl Aspect for CachingAspect {
    fn around(&self, pjp: ProceedingJoinPoint) -> Result<Box<dyn Any>, AspectError> {
        let key = format!("{}:{}", pjp.context().module_path, pjp.context().function_name);
        if let Some(cached) = self.cache.get(&key) {
            return Ok(cached);
        }
        let result = pjp.proceed()?;
        self.cache.insert(key, result.clone());
        result
    }
}

// vernal-aop 移植版（异步）
#[async_trait]
impl Interceptor for CachingAspect {
    async fn intercept(&self, inv: Arc<Invocation>, next: Next) -> InvocationResult {
        let key = format!("{}:{}", inv.operation().component(), inv.operation().method());
        if let Some(cached) = self.cache.get(&key) {
            return Ok(cached);
        }
        let result = next.run().await;
        if let Ok(value) = &result {
            self.cache.insert(key, value.clone()).await;
        }
        result
    }
}
```

| Pointcut 表达式 | AspectJ 表达式（依赖 Weaver）| 🎯 **Rust 原生 DSL**（execution/within + &&/\|\|/!）| 移植 aspect-rs DSL + 扩展 tag/qualifier |
| 声明式绑定 | `@Aspect`/`@Pointcut` 注解 + XML | 🎯 **`#[advice]` 宏** | 移植 `#[advice]` + 新增 `#[advised]` |
| 业务切面 | 仅调试工具（13 类）| 🎯 **8 个生产级切面**（caching/circuitbreaker/ratelimit）| A3 移植 aspect-std + S5 移植 spring 工具 |
| 执行模型 | 运行时反射 | 编译期宏织入（逐函数）| 启动期预编译（InvocationPlan）|
| 异步 | Reactor（Mono/Flux）| 同步 | Tokio-first（原生 async/await）|

### 核心结论

aspect-rs 在 **Pointcut DSL + 声明式宏 + 业务切面** 三个维度是 spring-aop 的
Rust 原生等价物，**直接补强 vernal-aop 的 S2/S4/S5/S7 阶段**：

1. **S2（Pointcut 体系）**：移植 aspect-rs DSL，工作量 3 天 → 2 天
2. **S4（AspectJ 表达式）**：移植 aspect-rs parser，工作量 5 天 → **1 天**（最大节省）
3. **S5（Interceptor 工具）**：移植 aspect-std 8 切面，工具箱从 9 个（spring 调试类）
   扩展到 17 个（+8 个业务切面）
4. **S7（Proxy 工厂）**：参考 aspect-rs `#[advice]` 宏设计，简化 `#[advised]` 宏
