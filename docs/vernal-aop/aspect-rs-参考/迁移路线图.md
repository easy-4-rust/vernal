# aspect-rs 参考迁移路线图（vernal-aop 第三蓝本）

> 版本：v1.0（2026-07-27）｜基线：aspect-rs @ main（aspect-core 0.1.2 + aspect-macros + aspect-std）
> 仓库：easy-4-rust/vernal @ dev ｜ 本文档随代码同步维护，每阶段完成时更新
> 蓝本定位：**继 spring-aop、tx_di 之后的第三个参考蓝本**，与 `docs/vernal-aop/`
> 下基于 spring-aop 的 3 份文档互补

## 一、总目标

本文档不是把 aspect-rs 整体迁移为 vernal-aspect crate，而是把 aspect-rs 作为
**第三个参考蓝本**，提炼其设计中**优于 spring-aop / tx_di 的 Rust 原生部分**，
补强现有 vernal-aop（52 文件异步 Around 内核）。

### 三个蓝本的定位与互补

| 蓝本 | Advice 形态 | Pointcut 模型 | 织入机制 | 对 vernal-aop 的价值 |
|---|---|---|---|---|
| **spring-aop** | Before/After/AfterReturning/Throws/Around/Introduction 六类 | ClassFilter + MethodMatcher + AspectJ 表达式 | CGLIB 字节码 + JDK 动态代理 | **语义丰富度**（6 类 Advice + AspectJ 表达式）|
| **tx_di aop.rs** | Before/After/Around 同步三段式 | 方法名 + 命名参数 | OnceLock + 宏生成包装 | **同步 Advice 形态参考**（本地实现）|
| **aspect-rs**（本蓝本）| Before/After/AfterError/Around 同步四段式 | **Pointcut DSL**（Execution/Within + And/Or/Not + 解析器）| `#[aspect]` / `#[advice]` 过程宏 | **Pointcut DSL 解析器 + 声明式宏 + 内置切面库** |

### 为什么把 aspect-rs 列为第三蓝本

aspect-rs 有三个 spring-aop / tx_di 都不具备的独特优势：

1. **Pointcut DSL 解析器**：aspect-rs 自带了 `parse_pointcut` 函数 + 完整的
   `Pointcut` AST（`Execution` / `Within` / `And` / `Or` / `Not`）+ `Matcher` trait。
   spring-aop 依赖 AspectJ Weaver（🚫 不迁移），vernal-aop 规划中要自实现
   AspectJ 表达式解析器（S4 阶段，5 天工作量）。**aspect-rs 的解析器可直接移植**，
   把 5 天工作量降到 ~1 天。

2. **声明式 advice 宏**：`#[advice(pointcut="execution(pub fn *(..)) && within(crate::api)", advice="around", order=10)]`
   把 Pointcut 表达式直接写在函数上。这比 spring-aop 的 XML/注解配置更 Rust 原生，
   也比 vernal-aop 规划的 `#[advised]` 宏（仅绑定 Advisor）更**声明式**。

3. **aspect-std 8 个内置切面**：authorization/caching/circuitbreaker/logging/metrics/
   ratelimit/timing/validation。spring-aop 的 `interceptor` 包（13 类）多是 trace/monitor
   等调试工具，而 aspect-std 是**生产级业务切面**，直接补强 vernal-aop S5 阶段
   （Interceptor 工具）的工具箱。

### 不做的事（明确边界）

- ❌ **不新建 vernal-aspect crate**：vernal-aop 已有完整异步内核，aspect-rs 作为
  参考蓝本融入现有 crate，不另起炉灶
- ❌ **不替换 vernal-aop 的异步 Around**：aspect-rs 是同步模型，vernal-aop 的
  Tokio-first 异步 Around 是正确方向，保留
- ❌ **不照搬 aspect-rs 的 Pointcut DSL 替代 spring-aop 对标**：两者**共存**，
  aspect-rs DSL 作为 spring-aop AspectJ 表达式的 Rust 原生子集实现
- ❌ **不迁移 aspect-driver / aspect-rustc-driver / cargo-aspect**：这些是
  rustc 编译期织入工具链，vernal-aop 用过程宏替代

### 与现有 3 份 spring-aop 文档的关系

| 现有文档（docs/vernal-aop/）| 本文（aspect-rs-参考/）的关系 |
|---|---|
| `迁移路线图.md` S1 Advice 体系 | aspect-rs 的 `Aspect` trait（before/after/after_error/around）直接验证 S1 设计可行 |
| `迁移路线图.md` S2 Pointcut 体系 | aspect-rs 的 `Pointcut` AST + `parse_pointcut` **加速 S2**，提供现成解析器 |
| `迁移路线图.md` S4 AspectJ 表达式 | aspect-rs 的 `Execution` / `Within` / `And` / `Or` / `Not` 是 AspectJ 的 Rust 原生子集，**降低 S4 工作量** |
| `迁移路线图.md` S5 Interceptor 工具 | aspect-std 的 8 个切面**扩展 S5 工具箱**（业务切面 vs Spring 的调试工具）|
| `迁移路线图.md` S7 Proxy 工厂 | aspect-macros 的 `#[aspect]` / `#[advice]` **简化 S7** 的 `#[advised]` 宏设计 |

## 二、aspect-rs 真实结构（联网核实）

### aspect-core crate（核心抽象）

```
aspect-core/src/
├── lib.rs                       # 门面（4 个 pub mod + prelude）
├── aspect.rs                    # Aspect trait（before/after/after_error/around）
├── joinpoint.rs                 # JoinPoint / Location / ProceedingJoinPoint
├── error.rs                     # AspectError（ExecutionError/WeavingError/Custom）
└── pointcut/                    # Pointcut DSL（aspect-rs 的核心价值）
    ├── mod.rs                   # 对外暴露 Pointcut/Matcher/parse_pointcut 等
    ├── ast.rs                   # Pointcut enum（Execution/Within/And/Or/Not）
    ├── pattern.rs               # ExecutionPattern/ModulePattern/NamePattern/Visibility
    ├── matcher.rs               # Matcher trait + FunctionInfo
    └── parser.rs                # parse_pointcut 函数（字符串 → Pointcut AST）
```

```
aspect-macros/src/
├── lib.rs                       # #[aspect] + #[advice] 两个 proc_macro_attribute
├── aspect_attr.rs               # #[aspect(Logger)] 转换逻辑
├── advice_macro.rs              # #[advice(pointcut=..., advice=..., order=...)]
├── parsing.rs                   # syn 解析
└── codegen.rs                   # TokenStream 生成
```

### aspect-std crate（8 个内置切面）

```
aspect-std/src/

├── circuitbreaker.rs            # 熔断切面

└── validation.rs                # 校验切面
```

## 三、对 vernal-aop 的价值评估

### 3.1 高价值（直接吸收，工作量减少）

| aspect-rs 概念 | vernal-aop 对应阶段 | 价值 | 吸收方式 |
|---|---|---|---|
| `Pointcut` AST（Execution/Within/And/Or/Not）| S2 Pointcut + S4 AspectJ | ⭐⭐⭐⭐⭐ | 移植 AST 到 `vernal-aop/src/pointcut/dsl/` |
| `parse_pointcut` 函数 | S4 AspectJ 表达式解析器 | ⭐⭐⭐⭐⭐ | 移植解析器，5 天 → 1 天 |
| `Matcher` trait + `FunctionInfo` | S2 Pointcut | ⭐⭐⭐⭐ | 改名为 `PointcutMatcher` + `FunctionDescriptor`，接入 Operation |
| `ExecutionPattern` / `ModulePattern` / `NamePattern` / `Visibility` | S2 Pointcut | ⭐⭐⭐⭐ | 移植模式类型 |
| `#[advice(pointcut=..., advice=..., order=...)]` 宏 | S7 `#[advised]` 宏 | ⭐⭐⭐⭐ | 参考 AdviceArgs 设计，扩展 vernal-aop 宏 |

### 3.2 中价值（部分参考）

| aspect-rs 概念 | vernal-aop 对应 | 处理 |
|---|---|---|
| `Aspect` trait（before/after/after_error/around 同步）| S1 Advice 体系 | **形态参考**：验证同步 Advice 可行，但 vernal-aop 保持异步 Around 为主 |
| `ProceedingJoinPoint::proceed()` | 现有 `Next::run()` | 已有等价物，**不替换** |
| `JoinPoint`（function_name/module_path/location）| 现有 `Operation`（component/method/metadata）| Operation 更通用，**保留** |
| `AspectError`（ExecutionError/WeavingError/Custom）| S5 异常体系 | **类型参考**：补充 vernal 的 `WeavingError` 变体 |
| aspect-std 8 个切面 | S5 Interceptor 工具 | **扩展工具箱**：caching/circuitbreaker/ratelimit 是 spring-aop 没有的业务切面 |

### 3.3 低价值（不吸收）

| aspect-rs 概念 | 原因 |
|---|---|
| `#[aspect(Logger)]` 直接绑定宏 | vernal-aop 用 `InvocationPlanCatalog` 预编译，比 aspect-rs 的逐函数织入更高效 |
| 同步 `around` 默认实现调用 before/after/after_error | vernal-aop 是异步 Around，无法直接复用同步默认实现 |
| `Location`（file/line 静态位置）| vernal-aop 的 `Operation` 更动态（component + method），`Location` 可作为元数据补充 |
| aspect-runtime 注册表 | vernal-aop 用 `InvocationPlanCatalog`（预编译目录）替代 |

## 四、吸收路线（分 3 个阶段）

### A1 — Pointcut DSL 移植（P0，预估 1 天）

**范围**：aspect-core/src/pointcut/ 全部 5 个文件 + parser

**目标文件**（新增到 vernal-aop）：

| 目标文件 | aspect-rs 源 | 工作量 |
|---|---|---|
| `src/pointcut/dsl/mod.rs` | `pointcut/mod.rs` | 0.1 天 |
| `src/pointcut/dsl/ast.rs` | `pointcut/ast.rs`（Pointcut enum）| 0.2 天 |
| `src/pointcut/dsl/pattern.rs` | `pointcut/pattern.rs`（ExecutionPattern/ModulePattern/NamePattern/Visibility）| 0.2 天 |
| `src/pointcut/dsl/matcher.rs` | `pointcut/matcher.rs`（Matcher + FunctionInfo）| 0.2 天 |
| `src/pointcut/dsl/parser.rs` | `pointcut/parser.rs`（parse_pointcut）| 0.3 天 |

**改造点**：
- `FunctionInfo` → 改名 `FunctionDescriptor`，新增 `tags: Vec<String>` 和
  `qualifier: Option<String>`，接入 vernal-aop 的 `Operation`
- `Matcher::matches(&FunctionInfo)` → 扩展为匹配 vernal `Operation`
- `Pointcut` AST 的 `Execution` / `Within` 保留，新增 `Tag` / `Qualifier` 变体
  （对接现有 `TagPointcut` / `QualifierPointcut`）

**验收**：`Pointcut::parse("execution(pub fn save_*(..)) && within(crate::api)")`
能解析并匹配；与现有 8 个 Pointcut（And/Or/Not/Any/Method/Component/Tag/Qualifier）共存。

---

### A2 — 声明式 Advice 宏参考（P1，预估 1.5 天）

**范围**：aspect-macros 的 `#[advice]` 宏 + `AdviceArgs` 设计

**目标**：扩展 vernal-aop S7 规划的 `#[advised]` 宏，增加 `#[advice]` 声明式宏

| 目标 | aspect-rs 参考 | 工作量 |
|---|---|---|
| `vernal-macros/src/advice_macro.rs` | `#[advice(pointcut=..., advice=..., order=...)]` | 1 天 |
| `vernal-macros/src/advice_args.rs` | `AdviceArgs` 结构体 | 0.5 天 |

**用法对比**：

```rust
// aspect-rs 原版（同步）
#[advice(
    pointcut = "execution(pub fn *(..)) && within(crate::api)",
    advice = "around",
    order = 10
)]
fn log_advice(pjp: ProceedingJoinPoint) -> Result<Box<dyn Any>, AspectError> {
    println!("before");
    let r = pjp.proceed()?;
    println!("after");
    r
}

// vernal-aop 移植版（异步）
#[advice(
    pointcut = "execution(pub fn *(..)) && within(crate::api) || tag(secured)",
    advice = "around",
    order = 10
)]
async fn log_advice(inv: Arc<Invocation>, next: Next) -> InvocationFuture {
    println!("before");
    let r = next.run().await;
    println!("after");
    r
}
```

**改造点**：
- `advice = "around"` 支持 `before` / `after` / `after_returning` / `after_throwing` / `around` 五类
- `pointcut` 表达式支持 `tag(...)` / `qualifier(...)` 扩展（aspect-rs 原生无）
- 函数签名改为 vernal 异步（`Arc<Invocation>, Next -> InvocationFuture`）

**验收**：`#[advice]` 宏能注册 advice 函数到 `InvocationPlanCatalog`；
5 种 advice 类型经 `advice_adapter` 转换为异步 Around。

## 六、工程规范

### 命名规则（与 vernal-aop 一致）

| aspect-rs 原名 | vernal-aop 移植名 | 原因 |
|---|---|---|
| `Pointcut`（AST enum）| `PointcutExpr`（避免与现有 `Pointcut` trait 冲突）| 现有 trait 保留 |
| `FunctionInfo` | `FunctionDescriptor` | 避免与 `Operation` 概念混淆 |
| `Matcher` trait | `PointcutMatcher` | 避免与现有 Pointcut trait 冲突 |
| `parse_pointcut` 函数 | `parse_pointcut_expr` | 同上 |
| `Aspect` trait | 不移植（与现有 `Interceptor` 冲突）| vernal-aop 保持 Around 为主 |
| `ProceedingJoinPoint` | 不移植（用现有 `Next`）| 已有等价物 |

### 文件结构规范

```rust
//! 对应 aspect-rs：aspect-core/src/pointcut/ast.rs::Pointcut
//!
//! Pointcut 表达式 AST（Rust 原生子集）。
//! 移植自 aspect-rs，扩展支持 tag/qualifier 匹配。

use super::pattern::{ExecutionPattern, ModulePattern, TagPattern, QualifierPattern};

/// Pointcut 表达式 AST 节点。
///
/// 对应 aspect-rs 的 `Pointcut` enum，扩展了 `Tag` 和 `Qualifier` 变体
/// 以支持 vernal-aop 的标签/限定符匹配。
#[derive(Debug, Clone, PartialEq)]
pub enum PointcutExpr {
    /// 匹配函数执行（移植自 aspect-rs）
    Execution(ExecutionPattern),
    /// 匹配模块内的函数（移植自 aspect-rs）
    Within(ModulePattern),
    /// 匹配标签（vernal-aop 扩展）
    Tag(TagPattern),
    /// 匹配限定符（vernal-aop 扩展）
    Qualifier(QualifierPattern),
    /// 逻辑与
    And(Box<PointcutExpr>, Box<PointcutExpr>),
    /// 逻辑或
    Or(Box<PointcutExpr>, Box<PointcutExpr>),
    /// 逻辑非
    Not(Box<PointcutExpr>),
}
```
