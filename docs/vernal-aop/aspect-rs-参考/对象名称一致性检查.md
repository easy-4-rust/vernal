## 二、名称冲突需改名的 6 个对象（关键）

以下 aspect-rs 对象与 vernal-aop 现有类型**同名或语义冲突**，移植时**必须改名**：

| aspect-rs 原名 | 冲突对象 | vernal-aop 移植名 | 冲突原因 | 处理 |
|---|---|---|---|---|
| `Pointcut`（AST enum）| 现有 `Pointcut` trait（基于 Operation）| **`PointcutExpr`** | 名称直接冲突 | 改名避免歧义 |
| `Matcher` trait | （潜在歧义）| **`PointcutMatcher`** | 避免与未来类型冲突 | 改名 |
| `FunctionInfo` struct | 与 `Operation` 概念混淆 | **`FunctionDescriptor`** | 语义重叠 | 改名 |
| `parse_pointcut` 函数 | 与 `Pointcut::parse` 关联 | **`parse_pointcut_expr`** | 强调解析表达式 | 改名 |
| `Aspect` trait | 与未来 `vernal-aop::Aspect` 概念冲突 | **不移植** | 与现有 `Interceptor` 冲突 | 🚫 不移植 |
| `JoinPoint` struct | 与现有 `Invocation` 概念冲突 | **不移植** | Operation 更通用 | 🚫 不移植 |

### 改名详细理由

#### 1. `Pointcut` → `PointcutExpr`（最关键）

```
vernal-aop 现有：
  pub trait Pointcut { fn matches(&self, operation: &Operation) -> bool; }
  （8 个实现：AndPointcut/OrPointcut/NotPointcut/AnyPointcut/MethodPointcut/...）

aspect-rs：
  pub enum Pointcut { Execution(...), Within(...), And(...), Or(...), Not(...) }

冲突：两者都叫 Pointcut，但一个是 trait（运行期匹配），一个是 enum（AST 节点）
解决：aspect-rs 的 enum 改名为 PointcutExpr（表达式 AST），与现有 Pointcut trait 共存
```

#### 2. `Matcher` → `PointcutMatcher`

```
aspect-rs：pub trait Matcher { fn matches(&self, function: &FunctionInfo) -> bool; }
冲突：未来 vernal-aop 可能有其他 Matcher（如 AOP Matcher / Non-AOP Matcher）
解决：改名 PointcutMatcher，明确职责是 Pointcut 匹配
```

#### 3. `FunctionInfo` → `FunctionDescriptor`

```
aspect-rs：pub struct FunctionInfo { name, module_path, visibility, return_type }
vernal-aop：pub struct Operation { component, method, metadata }
冲突：FunctionInfo 与 Operation 都是"函数信息"，容易混淆
解决：FunctionInfo 改名 FunctionDescriptor，作为 Pointcut 匹配用的中间结构，
      从 Operation 转换而来
```

#### 4. `parse_pointcut` → `parse_pointcut_expr`

```
aspect-rs：pub fn parse_pointcut(input: &str) -> Result<Pointcut, String>
冲突：函数返回 Pointcut（已改名 PointcutExpr），函数名需对应
解决：改名 parse_pointcut_expr
```

#### 5-6. `Aspect` / `JoinPoint` → 不移植

```
aspect-rs：
  pub trait Aspect { fn before/after/after_error/around }
  pub struct JoinPoint { function_name, module_path, location }

vernal-aop 现有等价物：
  pub trait Interceptor { fn intercept(inv, next) -> Future }  （异步 Around）
  pub struct Operation { component, method, metadata }  （更通用）

冲突：
  - Aspect（同步四段式）vs Interceptor（异步 Around）：执行模型不同
  - JoinPoint（静态）vs Operation（动态 + tags/qualifier）：Operation 是超集

解决：不移植，用现有等价物。aspect-rs 的 Aspect 仅作 S1 Advice 体系的形态参考
```

## 七、业务逻辑一致性检查

### ✅ 将完全一致的逻辑（移植后）

- Pointcut DSL 表达式解析（`execution` / `within` / `&&` / `||` / `!`）
- Pattern 匹配（`Wildcard` / `Exact` / `Prefix` / `Suffix` / `Contains`）
- Visibility 匹配（`Public` / `Crate` / `Super` / `Private`）
- ModulePattern 的前缀匹配（含 `::`）
- 8 个业务切面的核心语义（caching/ratelimit/circuitbreaker 等）

### ⚠️ 形态不同但语义等价的逻辑（异步化改造）

- `Aspect::around`（同步）→ `Interceptor::intercept`（异步）
- `ProceedingJoinPoint::proceed()`（同步）→ `Next::run().await`（异步）
- `AspectError`（同步错误）→ `InvocationError`（异步错误）
- aspect-std 切面的同步 `impl Aspect` → 异步 `impl Interceptor`

### ❌ 不移植的逻辑

- `Aspect` trait 的默认 `around` 实现（调用 before→proceed→after/after_error）
  - 原因：vernal-aop 异步 Around 无默认实现，强制用户显式实现
  - 但 `advice_adapter`（S1）可借鉴此模式实现异步包装
- `#[aspect(Logger)]` 的逐函数织入
  - 原因：vernal-aop 用 `InvocationPlanCatalog` 预编译，更高效
- aspect-runtime / aspect-driver 的 rustc 织入
  - 原因：用过程宏替代

### 🆕 vernal-aop 扩展的逻辑（无 aspect-rs 对偶）

- `tag(name)` / `qualifier(name)` Pointcut 语法
- `PointcutExpr::Tag` / `PointcutExpr::Qualifier` AST 节点
- `FunctionDescriptor` 的 `tags` / `qualifier` 字段
- `#[advice]` 宏的 5 类 advice 类型（aspect-rs 仅 `around`）
- `PointcutMatcher::matches_operation(&Operation)`（接入 vernal Operation）

## 八、命名规范总结（吸收 aspect-rs 后的最终规则）

| 规则 | 说明 | 示例 |
|---|---|---|
| Pointcut trait（运行期匹配）保留原名 | 现有 8 个 Pointcut 不变 | `AndPointcut` / `TagPointcut` |
| Pointcut AST 改名 `PointcutExpr` | 避免与 trait 冲突 | `PointcutExpr::Execution(...)` |
| Pattern 类型保留原名 | 无冲突 | `Visibility` / `NamePattern` |
| Matcher 改名 `PointcutMatcher` | 明确职责 | `PointcutMatcher::matches_operation` |
| FunctionInfo 改名 `FunctionDescriptor` | 避免与 Operation 混淆 | `FunctionDescriptor::from_operation` |
| 业务切面用 `_aspect` 后缀 | 与 spring `_interceptor` 区分 | `caching_aspect.rs` |
| `#[advice]` 宏保留原名 | 与 aspect-rs 一致 | `#[advice(pointcut=..., advice=...)]` |
| `#[advised]` 宏保留原名（S7）| 与 aspect-rs `#[aspect]` 区分 | `#[advised(advisors=[...])]` |

## 九、结论

| 维度 | 结果 |
|------|------|
| 名称完全一致（直接移植）| **14/23 = 60.9%** |
| 名称冲突需改名 | **6/23 = 26.1%**（Pointcut/Matcher/FunctionInfo 等）|
| 不移植（已有等价物）| **5/23 = 21.7%** |
| vernal-aop 扩展 | **7 个**（Tag/Qualifier DSL 等）|
| 核心冲突解决 | `Pointcut` enum → `PointcutExpr`（最关键）|

### 关键发现

1. **aspect-rs 的 Pattern 体系（4 类）零冲突直接移植**——`Visibility`/`NamePattern`/
   `ExecutionPattern`/`ModulePattern` 名称与 vernal-aop 无冲突
2. **aspect-rs 的 aspect-std 8 个切面零冲突直接移植**——只需异步化改造
3. **唯一硬冲突是 `Pointcut`**——aspect-rs 的 enum 与 vernal-aop 的 trait 同名，
   改名 `PointcutExpr` 解决
4. **`Aspect` trait 不移植**——异步 vs 同步执行模型冲突，用现有 `Interceptor` 替代

### 下一步行动

1. **A1（P0，1 天）**：移植 Pointcut DSL（5 文件），重点解决 `Pointcut` → `PointcutExpr` 改名
2. **A2（P1，1.5 天）**：移植 `#[advice]` 宏，扩展为 5 类 advice
3. **A3（P2，2 天）**：移植 aspect-std 8 个业务切面，异步化 + 接入 Rust crate（moka/governor/failsafe）
