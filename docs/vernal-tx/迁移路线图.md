# vernal-tx 全量迁移路线图

> 版本：v1.0（2026-07-27）｜基线：Spring Framework **7.0.8**（spring-tx）
> 仓库：easy-4-rust/vernal @ dev ｜ 本文档随代码同步维护，每阶段完成时更新

## 一、总目标

以 Spring Framework 7.0.8 的 spring-tx 模块为蓝本，结合 Rust 生态中 sqlx / diesel /
sea-orm / rbatis 的事务模型，实现 **功能语义完全对齐** 的 vernal-tx crate，**目标
116 个 Rust 文件**（不含 `lib.rs` / `mod.rs`），覆盖事务核心接口、抽象支持类、声明式
拦截器、@Transactional 注解、事务事件、反应式事务、JTA/JCA、DAO 异常体系。

### 设计原则

1. **功能语义对齐，实现方式 Rust 化**
   - Java `interface` → Rust `trait`
   - Java `abstract class` → Rust trait + 默认实现结构体
   - Java `ThreadLocal` → tokio `task_local!` 或 `thread_local!`
   - Java `MethodInvocation` / `aopalliance` → vernal-aspects 的 `Advice` / `Pointcut`
   - Java `@Transactional` / `@TransactionalEventListener` → `#[vernal::transactional]` /
     `#[vernal::transactional_event_listener]` 过程宏
   - Java `@EnableTransactionManagement` → vernal-context 的 `EnableTransactionManagement`
     模块注册
2. **一个 Java 类对应一个 Rust 文件**：对齐 liteflow-rust 的一文件一对象规范
3. **所有公开类型必须有中文文档注释**：结构体、枚举、trait、方法、字段
4. **模块路径 snake_case**，类型 PascalCase，方法 snake_case
5. **不实现 JTA 完整规范**：仅保留 JTA 接口抽象，运行时由后端提供方实现；同 Spring
   7.x 不再内置应用服务器嵌入式事务协调器
6. **DAO 异常按是否瞬时分层**：保留 `DataAccessException` 顶层，`TransientDataAccessException`
   / `NonTransientDataAccessException` 二级抽象
7. **JCA 端点**：仅保留 trait 抽象（`MessageEndpointFactory`），不内置 JCA WorkManager
   适配，集成由应用层完成

## 四、工程规范

### 命名规则

| 项目 | 规范 |
|------|------|
| 目录/文件名 | snake_case（`abstract_platform_transaction_manager.rs`、`jta_transaction_manager.rs`） |
| 类型名 | PascalCase（`AbstractPlatformTransactionManager`） |
| 方法名 | snake_case（`get_transaction`、`rollback_only`） |
| 参数名 | 与 Java 一致（`transaction_definition`、`rollback_only`） |
| 模块分组 | 按 Java 包分 mod（`transaction`、`transaction.support`、`transaction.annotation` 等） |
| 异常类统一前缀 | 与 Java 命名一致（如 `TransactionException`、`DataAccessException`） |
| trait 统一后缀 | trait 类保留 PascalCase 不带前缀；data 类（如 `TransactionTemplate`）按 Spring 命名 |

### 文件结构规范

```rust
//! 对应 Java 类：org.springframework.transaction.support.AbstractPlatformTransactionManager
//!
//! 平台事务管理器的抽象基类。
//! 实现了 Spring 的标准事务工作流（传播行为、挂起/恢复、同步回调），
//! 子类只需实现具体的 begin/commit/rollback 模板方法。

/// 平台事务管理器的抽象基类。
///
/// 对应 Spring 的 `AbstractPlatformTransactionManager`。
/// 实现了事务传播行为的全部分支（PROPAGATION_REQUIRED ... PROPAGATION_NEVER），
/// 子类只需提供具体的事务资源操作。
pub struct AbstractPlatformTransactionManager {
    /// 事务同步激活策略（SYNCHRONIZATION_ALWAYS/ON_ACTUAL/NEVER）
    transaction_synchronization: i32,
    /// 缺省超时（秒）
    default_timeout: i32,
    /// 是否在 commit 时校验已存在事务的隔离级别
    validate_existing_transaction: bool,
}

impl AbstractPlatformTransactionManager {
    /// 创建一个默认配置的抽象事务管理器。
    #[must_use]
    pub fn new() -> Self {
        Self {
            transaction_synchronization: SYNCHRONIZATION_ALWAYS,
            default_timeout: -1,
            validate_existing_transaction: false,
        }
    }
}
```

### 测试规范

  × 异常传播的全组合（约 50+ 测试）
- `TransactionTemplate.execute` 覆盖 callback + withoutResult + 异常回滚

## 五、风险评估

| 风险 | 影响 | 对策 |
|------|------|------|
| Spring-tx 7 个子包、113 个 Java 类，工作量大 | 单期完成 20+ 天 | 分 15 阶段分阶段验收 |
| JTA / JCA 涉及 Jakarta EE 规范，Rust 生态没有现成适配 | 抽象成本高 | 只提供 trait 抽象，运行时由集成层提供具体实现 |
| ThreadLocal → task_local 需要重新设计 reactive 路径 | reactor context 与 task_local 双向桥接复杂 | 优先 thread_local，reactive 单列实现 |
| `AbstractPlatformTransactionManager` 状态机复杂（嵌套事务/挂起/恢复） | 实现 bug 多 | mock 子类覆盖全部分支后再做 trait 抽取 |
| DAO 异常体系 25 个类 | 工作量大 | 一次写完 + derive 宏批量实现 |
| @Transactional 宏需要为 sync / async / generic / Box<dyn Fn> 四种签名生成代码 | trybuild UI 测试设计复杂 | 提供 `quote!` 模板按 ast 类型分支 |
| sqlx / sea-orm 跨后端 API 不同 | 适配层需要多份 | 一期只做 sqlx，后续按需扩展 |
| 与 vernal-aspects / vernal-context / vernal-beans 的集成测试 | 跨 crate 联调 | 在 examples/ 下做端到端测试 |
