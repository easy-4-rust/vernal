# spring-tx → vernal-tx 功能语义迁移对照表

基线：Spring Framework **7.0.8**（spring-tx），已覆盖 7.0 新增的
`TransactionExecutionListener`、`RollbackOn` 注解、`RestrictedTransactionalEventListenerFactory`
等语义。

迁移原则：**功能语义对齐，实现方式 Rust 化**。
Java 的接口/类分别映射为：trait / trait+结构体；
Java 的 `ThreadLocal` 映射为 tokio `task_local!`；
Java 的 `MethodInvocation` / AOP Alliance 委托给 vernal-aspects；
Java 的 `@Transactional` 映射为 `#[vernal::transactional]` 过程宏；
Java 的 `@EnableTransactionManagement` 映射为 vernal-context 的模块注册。

Rust 后端集成：以 **sqlx** 为第一目标后端（最流行、async-first、tokio 友好），
通过 `vernal-tx-sqlx` 适配 crate 把 `PlatformTransactionManager` 接口接到
`sqlx::Transaction` / `sqlx::Pool::begin`。diesel / sea-orm / rbatis 后续按需扩展。

状态图例：✅ 已迁移并有测试 / 🔶 语义等价但形态不同 / ⬜ 未迁移（路线图）/ 🚫 不迁移

**宏的实现要点**（S14）：
1. 解析属性 → `TransactionAttribute` 实例
2. 在函数体前/后插入 `let status = tx_manager.get_transaction(definition)?;` +
   `let result = #body;` + `if let Err(e) = &result { tx_manager.rollback(status) } else { tx_manager.commit(status) }`
3. 对 async 函数用 `async fn` 包裹
4. 对 impl block 中的 fn，自动识别 self 类型并自动注入 `Arc<dyn PlatformTransactionManager>`

## 二十一、特殊语义：vernal-tx 相对 Spring-tx 的偏差

| 偏差点 | 原因 | 处理 |
|--------|------|------|
| `PlatformTransactionManager` 三个方法是 sync（返回 Result） | 底层 sqlx 是 async | 在 trait 上增加 `async fn` 重载版本 `AsyncPlatformTransactionManager`，或 `BoxFuture` 返回 |
| `TransactionStatus` 没有 `isNewTransaction()` 字段 | 当前骨架只含 read_only/completed/rollback_only | S1 补 `is_new_transaction: bool` |
| `TransactionError` 是单一结构体而非 trait | 当前骨架简化 | S2 重设计为 trait + 13 个具体实现结构体 |
| 没有 `Default` 的事务管理器实现 | 当前只定义了 trait | S3-S5 给出完整 `AbstractPlatformTransactionManager` + 测试用 `ResTransactionManager` |
| 没有 thread-local 的事务上下文 | 异步优先 | 用 `tokio::task_local!` 替代 |
| 没有声明式 `@Transactional` | 骨架阶段 | S14 通过过程宏实现 |
| 隔离级别只有 enum，未与 sqlx 翻译 | 后端集成 | S13 实现 `vernal-tx-sqlx` |
| DAO 异常体系未建 | 未实现 | S2 一次性写完 25 类 |
| JTA / JCA 完整集成未做 | 仅 trait 抽象 | S10-S11 |
| reactive 包未实现 | 当前 reactive 在 `manager.rs` 提了一句但没真做 | S6 完整 13 文件 |
