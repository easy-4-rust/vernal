# vernal-context 全量迁移路线图

> 版本：v1.0（2026-07-27）｜基线：Spring Framework **7.0.8**（spring-context 主线）
> 仓库：easy-4-rust/vernal @ dev ｜ 本文档随代码同步维护，每阶段完成时更新

## 一、总目标

以 Spring Framework 7.0.8 的 spring-context 主线为蓝本，实现功能语义**已经基本对齐**
的 vernal-context crate。vernal-context 不再以"补缺"为主，而是进入**加固 + 收尾**
阶段：补齐剩余缺口、提升测试覆盖、巩固 tx_di 风格 API、收尾文档与中文注释。

### 当前真实状态（2026-07-27）

vernal-context **已实现** Spring 7.0.8 的几乎全部上下文契约；与 spring-context
的功能语义对齐度约 **90%**。剩余差距集中在三个方向：

1. **未对齐但 Spring 必须的契约**：`ApplicationContextAware` 生态、`HierarchicalBeanFactory`
   （父子 Context）、`Scope` 关闭的有界等待、Lifecycle `pause` / `restart` 显式入口
2. **Java 生态特有**（**不应迁移**）：XML 配置、ClassPath 扫描、LoadTimeWeaver、
   CGLIB 增强、Aware 注入系列、ConversionService、i18n
3. **vernal-context 应独立打磨**：测试覆盖率、文档、`PredicateCondition` 落地、
   `StartupReport` 序列化稳定性、ManagedTaskSupervisor 性能基线

### 设计原则

1. **功能语义对齐，实现方式 Rust 化**：Java 反射 → trait 对象；AnnotationProcessor →
   过程宏 + linkme；JVM shutdown hook → Tokio signal listener；Aware 注入 → IoC
   显式依赖注入
2. **每个 .rs 文件只对应一个 Java 对象**：对齐 vernal-expression / liteflow-rust
   的一文件一对象规范
3. **所有公开类型必须有中文文档注释**：结构体、枚举、trait、方法、字段
4. **模块路径 snake_case**，类型 PascalCase，方法 snake_case
5. **与 vernal 框架深度集成**：`ApplicationContext` 由 `vernal-beans::Container`
   驱动；`EventBus` 类型化广播；`ManagedTaskSupervisor` 两阶段停机
6. **不实现 XML / ClassPath 扫描**：Rust 生态主推过程宏 + 显式注册

## 四、工程规范

### 命名规则

| 项目 | 规范 |
|------|------|
| 目录/文件名 | snake_case（`application_context.rs`、`managed_task_supervisor.rs`）|
| 类型名 | PascalCase（`ApplicationContext`、`ManagedTaskSupervisor`）|
| 方法名 | snake_case（`refresh`、`is_pauseable`）|
| 参数名 | 与 Java 一致（`cancellation_token`、`runtime_handle`）|

### 文件结构规范

```rust
//! 对应 Java 接口：org.springframework.context.Lifecycle
//!
//! 异步可由 ApplicationContext 编排的组件契约。
//! 与 spring 的 Lifecycle 一致；vernal 额外保证：
//! - `stop` 必须能处理"已 initialize 但 start 未完成"的回滚场景；
//! - 异步 Future 在 cancel 时不会遗弃 Tokio task；
//! - `name()` 仅返回静态字符串，禁止拼接配置值或租户标识。

/// 异步生命周期组件契约。
///
/// 对应 Spring 的 [`Lifecycle`](https://docs.spring.io/spring-framework/docs/current/javadoc-api/org/springframework/context/Lifecycle.html)。
///
/// 实现类型必须作为 Singleton 注册到 Vernal IoC；Context 会按 IoC 依赖
/// 计划调用 `initialize` → `start`，关闭时按逆序调用 `stop`。
pub trait Lifecycle: Send + Sync + 'static {
    /// 返回用于诊断的组件名称。
    fn name(&self) -> &'static str {
        type_name::<Self>()
    }

    /// 单例构造完成后的异步初始化钩子。
    fn initialize(&self) -> LifecycleFuture<'_> {
        Box::pin(async { Ok(()) })
    }

    /// 启动组件。
    ///
    /// 组件应监听传入的取消令牌，并让自行派生的 Tokio task 在关闭时退出。
    fn start(&self, _cancellation: CancellationToken) -> LifecycleFuture<'_> {
        Box::pin(async { Ok(()) })
    }

    /// 释放初始化或启动阶段获得的资源。
    fn stop(&self) -> LifecycleFuture<'_> {
        Box::pin(async { Ok(()) })
    }
}
```

### 测试规范

- 每个公开 trait / struct 至少 1 个单元测试
- `ApplicationContext` refresh / start / close / pause / restart 每个状态机迁移
  至少 3 个集成测试
- 条件装配至少 5 个场景：present / missing / having_value / match_if_missing /
