# spring-beans ↔ tx_di ↔ vernal-beans 对象名称一致性检查

> 检查时间：2026-07-27
> 基线：Spring Framework 7.0.8 spring-beans + tx_di（Rust DI 实证项目）
> vernal-beans：36 文件 / 约 3600 行 / 32 测试（已存在）+ 目标新增 ~64 文件

## 一、本检查的目的

本文档回答一个核心问题：
**spring-beans 中的 335+ Java 类，与 tx_di 的 18+ Rust 模块，在 vernal-beans 中是否拥有一致的命名空间？**

具体而言：

1. **Java ↔ Rust 类型名是否对齐**（PascalCase ↔ snake_case）
2. **tx_di 模块是否在 vernal-beans 中有同名承接**
3. **跨链路是否出现命名冲突 / 重复 / 错位**
4. **未来新增时命名规范**

## 二、统计汇总

| 维度 | Spring | tx_di | vernal-beans | 说明 |
|------|--------|-------|--------------|------|
| 顶层类型总数 | ~335 | 18 | 36 | 排除 package-info / mod.rs / lib.rs |
| **完全匹配（PascalCase ↔ snake_case）** | 13 | 13 | — | 已存在 |
| **语义对齐但形态不同** | 12 | 8 | — | 8 已存在 + 12 形态差异 |
| **待迁移（路线图 ⬜）** | ~310 | — | — | 见 `对象级对照表.md` |
| **不迁移（🚫 Java 特有）** | ~30 | — | — | CGLIB/Groovy/XML/ClassLoader |

## 七、命名冲突 / 错位风险

### 7.1 命名冲突（已发现）

| 冲突项 | 现状 | 建议处置 |
|---|---|---|
| `Scope` 类型 | `component_scope.rs::Scope`（Singleton/Transient/Custom）| 保留（vernal 主要）；但 Spring 的 `Scope` 是 trait 风格（get/conversation/removeDestructionCallback）| S8 阶段新增 `scope.rs::Scope` trait（接口）+ `component_scope.rs::ScopeKind` enum（具体类型） |
| `Definition` vs `BeanDefinition` | vernal 用 `ComponentDefinition`（已存在），Spring 用 `BeanDefinition` | 保留 vernal 命名（更 Rust 风格），S2 阶段新增 `bean_definition.rs::BeanDefinition` trait 作为 Spring 风格接口 |
| `Component` trait | vernal 已用 `Component`（已存在）| 保留，Spring 的 `BeanDefinition` 通过 `BeanDefinition` trait 在 S2 阶段新增 |
| `Container` struct | vernal 已用 `Container`（已存在）| 保留，作为整体容器；Spring 的 `BeanFactory` 通过 `BeanFactory` trait 在 S3 阶段新增 |
| `qualifier` 文件 vs `Qualifier` 类型 | 一致 | ✅ |

### 7.2 命名错位

| 错位项 | 现状 | 建议处置 |
|---|---|---|
| `Container` vs `Store`（tx_di）| vernal 改名 Container | 接受（更贴近 Spring）|
| `ComponentDefinition` vs `ComponentMeta`（tx_di）| vernal 用 `ComponentDefinition` | 接受（更贴近 Spring）|
| `BuildPlan` vs `topo_sort` 结果（tx_di）| vernal 新增 `BuildPlan` | 接受 |
| `BeanUtil` vs `BeanUtils`（Spring）| vernal 用 `BeanUtil` | S18 文档说明为何单数（Rust 风格 + 工具是单数）|
| `Resolver` 类型（vernal 自研）| 与 Spring `TypeConverterDelegate.resolveTypeArgument` 不冲突 | ✅ |

### 7.3 路径错位

| 项 | 建议 |
|---|---|
| `Scope` 类型当前在 `component_scope.rs` | 建议未来 S8 阶段调整为 `scope.rs`，因为它对应 Spring 的 `Scope`（接口）而非 Spring 的某子类型 |
| `BeanError` 当前在 `bean_util.rs` | 建议 S2 阶段拆分为独立 `bean_error.rs`（对齐 Spring `BeanError` 命名意图）|
| `DefinitionError` 在 `definition_error.rs`，`ResolveError` 在 `resolve_error.rs` | ✅ 已对齐 |

## 九、命名规范（Vernal-Beans 强约束）

### 9.1 文件名

| 项 | 规范 | 违反示例 |
|---|---|---|
| 类型 | PascalCase，对齐 Spring 风格 | `BeanFactory`, `AutowiredAnnotation`, `ConfigurationClassPostProcessor` |
| 文件名 | snake_case 直接映射 PascalCase | `bean_factory.rs`, `autowired_annotation_bean_post_processor.rs` |
| 一个 Java 类对应一个 Rust 文件 | 是 | 把多个类合并到同一文件属历史遗留 |
| Spring 风格 `Bean` 前缀 | 保留 | `BeanDefinition`, `BeanFactory`, `BeanPostProcessor` |
| Spring 风格 `Aware` 后缀 | 保留 | `BeanNameAware`, `BeanFactoryAware`, `ApplicationContextAware` |
| Spring 风格 `PostProcessor` 后缀 | 保留 | `BeanPostProcessor`, `BeanFactoryPostProcessor`, `BeanDefinitionRegistryPostProcessor` |
| Spring 风格 `Resolver` / `Configurer` / `Editor` / `Registry` 后缀 | 保留 | `BeanDefinitionResolver`, `CustomEditorConfigurer`, `PropertyEditorRegistry` |

### 9.2 模块路径

| Spring 包 | vernal-beans 模块 | 备注 |
|---|---|---|
| `org.springframework.beans` | 顶层 | 不下沉 |
| `org.springframework.beans.factory` | 顶层 | 不下沉（高频） |
| `org.springframework.beans.factory.config` | 顶层 | 不下沉（高频） |
| `org.springframework.beans.factory.support` | 顶层 | 不下沉 |
| `org.springframework.beans.factory.annotation` | `annotation/` | 子目录 |
| `org.springframework.beans.factory.aot` | `aot/` | 子目录 |
| `org.springframework.beans.factory.parsing` | `parsing/` | 子目录 |
| `org.springframework.beans.factory.serviceloader` | `serviceloader/` | 子目录 |
| `org.springframework.beans.factory.wiring` | `wiring/` | 子目录 |
| `org.springframework.beans.factory.xml` | `xml/` | 子目录（弱化） |
| `org.springframework.beans.factory.groovy` | `groovy/` | 子目录（🚫） |
| `org.springframework.beans.propertyeditors` | 顶层 | 不下沉（30+ 编辑器）|
| `org.springframework.beans.support` | `support/` | 子目录 |

### 9.3 Spring 子包对齐策略

为避免目录无限膨胀：

- **不下沉的子包**：`factory`、`factory.config`、`factory.support`、`propertyeditors`、`support`
- **下沉为子目录的子包**：`annotation`、`aot`、`parsing`、`serviceloader`、`wiring`、`xml`、`groovy`（且需按路线图决定是否实现）

### 9.4 命名一致性附录：vernal-beans ↔ Spring ↔ tx_di

| vernal-beans | Spring | tx_di | 一致 |
|---|---|---|---|
